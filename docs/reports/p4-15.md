## Behaviour

**Tables (DEC-324 a):**
- `alert_rules`: `id` uuid, `workspace_id`, `name`, `type`, `target_type` (CHECK: product / watchlist / store / saved_screen / supplier_offer / test / all), `target_id` text, `params` jsonb, `enabled`, `muted_until`, `armed`, `last_value` jsonb, `last_evaluated_at`, `created_at`. UNIQUE `(workspace_id, id)` for the alerts FK. No `channel_ids`.
- `alerts`: `id` bigint, `workspace_id`, `rule_id` nullable, `type`, `entity_type`, `entity_id`, `dedupe_key` UNIQUE, `fired_at`, `payload` jsonb, `read_at`, `archived_at`. Index `(workspace_id, fired_at, id)` for the inbox.
- `workspace_id` is NOT NULL and indexed on both. FK `(workspace_id, rule_id)` → `alert_rules (workspace_id, id)` ON DELETE SET NULL (rule_id): an alert can't name another workspace's rule, and a deleted rule leaves its alerts.

**Evaluation (`pulso_core.alerts.evaluate(session, workspace_id, as_of)`, DEC-324 b–f):**
- Loads the workspace's enabled rules whose `muted_until` is null or ≤ `as_of`, and returns `{rule_id: "ok" | "no_source" | "skipped"}`. The caller commits.
- A rule watches supplier offers (live supplier listings): one offer, a product's offers, or every open test's product (the R-23 defaults).
- Metrics, point in time (`captured_at <= as_of`): cost from the listing snapshot's `price_min_minor`; freight from the cheapest US quote for one unit in the newest `shipping_options` capture; stock from `in_stock(available, stock)` on the newest snapshot that has a stock field.
- Crossing: the first value seen is the reference and never fires. Price and freight rules fire at |change| ≥ `pct` from the reference (default 5) and re-arm below `pct` × 0.95 (`HYSTERESIS = 0.05`). Stock rules fire on the flip. Only a new observation moves state.
- Dedupe: `rule_id:supplier_offer:listing_id:<UTC date of the crossing observation>`, ON CONFLICT DO NOTHING.
- Payload: `old` (reference value, currency, as_of), `new` (value, currency, as_of, source, raw_payload_id), `threshold`, `as_of` per source, `link` `/products/{id}/suppliers`.
- R-23: once a workspace has an open test, three Testing rules are seeded (cost, freight, stock-out). On those rules a crossing over a collection gap known by `as_of` is held: no alert, `last_value.skipped = {reason: "gap", from, to}`, the offer stays armed, and the next gap-free observation fires it.
- No source: a rule with nothing to read reports `no_source` and never fires.

**Endpoints (DEC-324 g).** The operation id is the function name:

| Endpoint | Operation id | Behaviour |
|---|---|---|
| `GET /v1/alert-rules?cursor=&limit=` | `list_alert_rules` | Newest first, keyset `[created_at, id]`, `limit` 1–100 (default 50). Each rule shows `status` and `skipped` from its last evaluation |
| `POST /v1/alert-rules` | `create_alert_rule` | 201. `type` is one of the four built types; `target_type` is `product` (an existing, unmerged product) or `supplier_offer` (an existing supplier listing). The id is normalised; an unknown target is a 404, a malformed one a 422. `params.pct` > 0, default 5 |
| `PATCH /v1/alert-rules/{id}` | `update_alert_rule` | `name`, `params`, `enabled`, `muted_until` (null unmutes). `type` and the target can't change (422). Null `name`, `params` or `enabled` is a 422 |
| `DELETE /v1/alert-rules/{id}` | `delete_alert_rule` | Returns the rule as it was; its alerts stay. A Testing default is a 409 `default_rule` |

Another workspace's rule answers 404 on PATCH and DELETE.

**Call site for SC-6 (brief item 5):** after scores in the nightly chain on the collector host, for each workspace: `pulso_core.alerts.evaluate(session, workspace_id, as_of=<run time>)`, then `session.commit()`, from a `pulso_workers` job. No task or Beat entry was added here.

**Acceptance, test by test:**
- **(a) A supplier cost that stays past threshold for 10 evaluations fires exactly one alert; crossing back past the hysteresis band and again fires a second.** `test_a_cost_past_its_threshold_fires_once_and_again_only_after_crossing_back`: 1000 → 1100 fires once; ten more evaluations at 1102–1111 add nothing; 1048 (4.8%, inside the 4.75–5% band) doesn't re-arm, so 1100 again adds nothing; 1040 (4%) re-arms and 940 (−6%) fires the second, with the reference 1000 as `old`. Also checks the dedupe key, `fired_at`, every payload field, `armed`, and that a muted and a disabled rule aren't evaluated.
- **(b) Re-running the same evaluation inserts no duplicate rows.** `test_rerunning_an_evaluation_inserts_no_duplicate`: a second run leaves one row, and so does a third run after the rule's state is reset to before the crossing (the dedupe key's ON CONFLICT).
- **(c) An R-23 cost change on a product in Testing fires once with old and new values; the same change with a collection gap in the window is skipped and the rule shows skipped: gap.**
  - `test_a_testing_product_gets_default_cost_freight_and_stock_alerts`: the three defaults are seeded once; cost 1000 → 1100, freight 500 → 600 and stock in → out each fire once with old and new values.
  - `test_a_testing_change_across_a_collection_gap_is_skipped`: the default cost rule returns `skipped`, writes no alert and records `{reason: "gap", from, to}` for the gap known by `as_of` (a gap detected later is left out). A re-run without new data still holds it, and the next gap-free observation fires it. The owner's own rule on the same offer fires through the gap.
- **(d) Two-workspace isolation for rules and alerts.** `test_rules_and_alerts_stay_in_their_workspace` (engine): evaluating A never touches B's rule; the database refuses an alert naming another workspace's rule; deleting a rule keeps its alert with a null `rule_id`. `test_rules_crud_validation_and_isolation` (API): B lists no rules and gets 404 on A's rule. `test_models.py::test_workspace_money_and_utc_contract` covers both tables' `workspace_id`.
- **(e) unread-count, read and archive endpoints tested.** Moved to WF-4a2 with the endpoints (see Split). Their test, `test_inbox_pages_filters_reads_and_archives`, is in the commit named there.
- **(f) Pin/schema tests updated for head 0021.** `test_models.py` (heads, 0021 → 0020 → 0019), `test_phase2_schema`, `test_phase3_schema`, `test_product_tests_schema`, `test_schema_integration` (base ↔ head round trip and `compare_metadata`, which accepts the `SET NULL (rule_id)` FK), `test_scores`.
