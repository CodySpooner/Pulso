### Why a hook in the dialog, not in the parent

The parent clears `confirm` (and the failure) on Cancel and on success. Keeping the value inside each dialog leaves the parent's rules alone: `inDialog`, the status line, and `clearFailure` decide where a failure shows (imp-123). It also fixes the closing frame in one place for both dialogs. The hook stores its snapshot with React's "adjust state while rendering" pattern, guarded by a per-value comparison, so it re-renders only when a value changes and needs no ref read during render (React Compiler lint). ActivityDialog had the same bug in the same file, so it gets the same one-line fix.

### The count rule (DEC-223)

- **Expired counts**, on an enabled source. The account has likely lapsed (`1600014`), so CJ collection stops working.
- **Warn doesn't.** It is a heads-up already on the row (amber "N days left" with its hint). Counting it would light the badge for up to 7 days before anything stops, and DEC-096 keeps the badge to "act now".
- **A disabled CJ doesn't count**, even when expired. DEC-096 keeps Disabled out of the badge because the owner chose it, and a disabled CJ runs nothing the lapse could stop. Re-enabling it would surface the problem as Failing or Blocked on the next run. This narrows the brief's default ("expired counts"), and DEC-223 (c) says why.
- **The reason on the row:** a counted CJ keeps its run-based pill, for example Healthy, since its last run did succeed. Directly under the pill is the red "Expired · −N days" line with its CircleX icon and hint (DEC-216 c), in the table and in the phone card. So a counted source never shows a Healthy pill alone. A pill of its own ("Lapsed") would need `StatePill` in `atoms.tsx`, which another branch owns (see Leftovers).
