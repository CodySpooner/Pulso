## The escaping elements (measured first)

A throwaway probe listed every `position: absolute` element inside `#main` with no positioned ancestor. Such an element's containing block is the viewport. Fixture data, E2E auth bypass, rebased tip with the fix reverted:

| Page, width | Escaping boxes | Lowest edge | Document height |
|---|---|---|---|
| `/admin/data-health`, 1440×900 | The CSV panel's two `sr-only` live regions, `<p role="status">` and `<p role="alert">` (`data-health/import-panel.tsx:244,247`), at the very end of the page | **1,319 px** | **1,319 px** |
| | 4 `sr-only` reason spans from `<Missing>`: "No source yet: the API doesn't serve uptime…" and "…backup size" (`summary-cards.tsx:117,173`), "No run recorded yet" and "Not collected yet" (`sources-table.tsx`; hidden at 1440) | 354 px | — |
| `/admin/data-health`, 375×812 | The same 6 | 2,268 px (inside the 2,675 px page) | 2,675 px (the document scrolls by design) |
| `/`, both widths | none | — | 900 / 1,918 px |

After the fix the same probe finds **0** escaping boxes on both pages at both widths (was 6 on Data Health).

**Why they escape:** at lg the shell is `h-dvh` and only `main` scrolls (`overflow-y-auto`). Overflow clips and scrolls only the descendants whose containing-block chain passes through the scroller. With no positioned ancestor, an absolute box's containing block is the viewport, so `main`'s overflow neither clips nor scrolls it. The box sits at its static position, the end of `main`'s content, and stretches the document. Only the two live regions reach past 900 px, so they alone cause the 419 px. imp-124 also mentioned "an svg"; the probe found no escaping svg on the rebased tip or on the earlier trial merge.

## The fix

`relative` on `<main>`. Every box a page renders now has `main` (or something inside it) as its containing block, so it belongs to `main`'s scroll area. Nothing that was already positioned changes containing block, clipping or paint order. Below lg, `main` isn't a scroller, so nothing moves on phones: page heights at 375 are identical before and after.

Alternatives, and why not (DEC-201):
- **`overflow: clip` on the shell root:** clipping skips boxes whose containing block sits above the clipping element, so it changes nothing here.
- **`relative` on the shell root.** I tried and measured it on `20889b7`. The document drops to 900 px, but the jump still moved the top bar 9 → −400 px: the live regions become scrollable overflow of the root's `overflow-hidden` box, and the jump scrolls that box instead. They would also stop scrolling with `main`. `e2e/shell-scroll.spec.ts` fails on it.
- **`contain: paint` on `main`:** it also makes `main` the containing block of `position: fixed` descendants.
- **`relative` on the CSV panel:** fixes one page, not the cause.
