**Metric:** CJ rows in Data Health showing an evidence-based activity status, **0 → 1/1**. Before this, `cj.activity.countdown` had no writer or reader (DEC-211 b).

## What shipped

**API** (`apps/api`):
- **`PUT /v1/admin/sources/cj/activity`** (operation id `put_cj_activity`; same admin dependency as the other admin routes).
  - The body, `ActivityEntry`, subclasses `pulso_sources.cj.activity.Evidence`, so every Evidence check runs: aware times converted to UTC, the transaction not after its observation, `amount_minor` a strict int above 0, `currency` three capitals, and extra fields rejected.
  - `kind` can only be `owner_entry`, so `csv_export`, `token_issuance`, `auth_response` and `api_order` all get a 422.
  - `currency` defaults to `USD`. `observed_at` defaults to the server's UTC now, and a body value in the future gets a 422.
- **The write:** `session.refresh(source, with_for_update=True)`, then `source.config = {**source.config, "cj_account_activity": entry.model_dump(mode="json")}`. That is the imp-149 pattern: it re-reads config under the row lock and changes only that key. It returns the CJ `SourceHealth`.
- **The read:** the `cj` item of `GET /v1/admin/sources` gains `activity` = `{state, days_remaining, as_of (transaction_at), observed_at}`, computed with `countdown(Evidence.model_validate(stored), now)`.
  - Missing or invalid stored evidence (a string, a list, a token-kind body, a partial body) reads `unknown` with every other field null, never an error and never 0.
  - Other sources omit the key (`exclude_if`), so it is optional in the schema.
- `apps/api/openapi.json` and `apps/web/src/lib/api/schema.d.ts` are regenerated with `pnpm gen:api`.

**Web** (`apps/web/src/components/data-health/`):
- `model.ts`:
  - `activityText`: "No evidence yet", "N days left", or "Expired · −N days" (U+2212 minus, so the sign carries the meaning without colour);
  - `toMinor`: amount string → minor units using the currency's own decimals (`Intl`), or null unless above 0.
- **`sources-table.tsx`, on the CJ row** (the table's Status cell, under the pill and notes; on a phone, an "Activity" line in the card), two lines:
  1. The countdown, with an icon and a hint on hover, focus or tap. `ok` is neutral (CircleCheck), `warn` amber (Clock), `expired` red (CircleX), `unknown` muted (CircleDashed).
  2. "Last order <UTC date>" (the evidence's as-of; the full order time, the entry time and the source on hover), then **Add order** or **Update order**. These are underlined like the row's other in-cell links.
- **The "Latest CJ order" dialog** (the ReasonDialog pattern):
  - fields: order date and time, read as UTC (`max` = the time it opened, so a future time is refused natively), the amount (`min 0.01`, then `toMinor`), and the currency (USD);
  - **Save order** closes the dialog, says "Order saved. CJ Dropshipping activity: N days left." in the panel's status line, refetches, and returns focus to the row's link;
  - a failed save stays in the dialog as an `ActionError` with its error ID; offline, it fails at once (`networkMode: "always"`);
  - Cancel or Escape sends nothing.
- **Clicks to enter evidence: 2** (Add order or Update order, then Save order). The date field is focused when the dialog opens, and Enter can stand in for the second click.

**States** of the new UI:
- loading: the row skeleton;
- no source yet / empty: "No evidence yet" with Add order;
- error: a failed save shows in the dialog; a failed load shows the panel error;
- stale: the panel's stale line, and the order date is always shown;
- offline: a save fails at once with the offline reason.

Keyboard: every control is a native button or input with the global focus ring. The dialog traps focus and returns it. Reduced motion: the only motion is the shared dialog's, under the global rule.
