## Decisions in brief (DEC-289)

- **Lookup key:** the user pastes the link or number each time, so Pulso stores no AliExpress id. Accepted: `http(s)` on `aliexpress.com` / `aliexpress.us` (any subdomain), path `/item/<digits>.html`, optional `skuId=`, or a bare number; ASCII digits only. Anything else is a 422 `invalid_link`.
- **Two operations:** GET never calls AliExpress, so tab focus and refetches can't spend the 500-a-day cap. POST runs the lookup.
- **Expiry:** the per-product copy expires at `as_of` + 24 h, absolute. An answer `lookup()` served from its own cache hours later still vanishes on time.
- **Gate order:** GET mirrors `lookup()`. The flag off hides everything; a cached answer shows until its 24 h end, even if the row was turned off since.
- **Where lookups run:** unchanged. The transport keeps the collector-host guard, so the API answers `disabled` until the owner turns the source on where the guard passes. The guard is not weakened.
- **§7.10:** no mark in Pulso's name, app name or page URLs. The API path `/v1/products/{id}/aliexpress` (named in the brief and DEC-283) names the source factually, like `sources.key`. A stricter owner reading means one router line plus `pnpm gen:api`.
- **Better option found in the vault note:** DS image search from the product's main image ("Find on AliExpress"). It needs no paste, but it is a new method to docs-check first, it returns candidates rather than one product, and it spends calls per view. Backlog.
