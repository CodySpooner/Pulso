## What shipped

`packages/sources/src/pulso_sources/cj/activity.py` (new, 59 lines) and `packages/sources/tests/cj/test_activity.py` (new, 25 tests). Fixtures only: no CJ request, no migration, no API shape change, no UI, no scheduler, no source change, no new dependency.

- **`Evidence`** (pydantic, frozen, `extra="forbid"`): the account's latest positive-amount transaction.
  - `kind`: `owner_entry` | `csv_export`; anything else (`token_issuance`, `auth_response`, `api_order`) is rejected.
  - `transaction_at`, `observed_at`: `AwareDatetime` converted to UTC; naive values are rejected, and so is a transaction after its observation.
  - `amount_minor`: `StrictInt > 0` (0, negatives, strings and `True` are rejected). `currency`: `^[A-Z]{3}$`.
- **`countdown(evidence, now) -> Status(state, days_remaining)`**, pure:
  - `unknown`, `None` when there is no evidence, or when it was observed after `now` (fails closed, never more than 30);
  - otherwise `days_remaining = 30 − (now's UTC date − transaction's UTC date)`: `ok` above `WARN_DAYS = 7`, `warn` at 1–7, `expired` at 0 or less (negative values say how long ago it likely lapsed);
  - a naive `now` raises `ValueError`.
- **Day count:** UTC calendar dates (AGENTS.md §3). So `expired` never comes later than 30 full days after the transaction, whatever timezone CJ counts in. CJ's own day boundary is unverified.
- **Never evidence:** token issuance, auth responses, API-created orders. The auth fixture body (and its `data`) fails validation.

## Not done, and why (DEC-211 b)

**Persistence.** The brief allowed it only without a migration. `sources.config` needs none, but nothing could write evidence without an API, UI or CSV-template change, all excluded here. A `sources.config` writer must also re-read the row under its lock (the imp-149 lost-write fix), which needs a PostgreSQL test. A writer with no caller would be dead code, so DEC-211 records where it goes instead:
- `Evidence.model_dump(mode="json")` under `sources.config.cj_account_activity`, written row-locked;
- read back with `Evidence.model_validate`, with invalid stored evidence treated as `unknown`;
- the status shown on the CJ row in Data Health.

**Open question (unchanged):** no fixture proves which CJ response or export establishes the latest positive transaction across the whole account. Until evidence is entered, activity is unknown.
