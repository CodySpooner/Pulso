## Change

- `apps/web/src/components/data-health/model.ts`: new pure, exported `runBlocker(host, source, online)`. It returns the reason Run now is unavailable, or null. The body and the three reason strings are the table's, byte for byte. `OFFLINE_HINT` stays in `components/shell/offline-banner.tsx`, where `atoms.tsx`, `data-health.tsx`, `import-panel.tsx` and the table's switch also read it, and `model.ts` imports it from there. Every importer of `model.ts` is a client module, so the constant crosses no server boundary. The parameters are `Pick<HostHealth, "live_runs_allowed"> | undefined` and `Pick<SourceHealth, "enabled">`, the only fields the rule reads.
- `sources-table.tsx`: the local `runBlocker` closure is gone. Run now gets `runBlocker(host.data, s, online)`.
- `run-drawer.tsx`: `canRun` is now `host.data != null && runBlocker(host.data, source, online) == null`.

Definitions of the rule: **2 → 1**. A grep for `live_runs_allowed` and the two reason strings under `apps/web/src` (tests and the generated schema excluded) finds them only in `model.ts`. The one exception is `summary-cards.tsx:104`, which shows the host flag on the Collector host card and is not part of the Run now rule.

### The two surfaces while the host call is unknown

The copies differed while the host call was loading or had failed. Both differences are kept:

| Host call | Table (Run now reason) | Drawer (never-run copy names Run now) |
|---|---|---|
| loaded, `live_runs_allowed: false` | "Live collectors run only on the collector host." | no |
| loaded, `true` | the enabled, then the offline reason, else none | only when there's no reason |
| loading or failed | the host gives no reason; enabled, then offline | **no** (as before: the old line needed `=== true`) |

The drawer's own condition is the `host.data != null` guard: its copy suggests Run now only once the host says live runs are allowed. The rule itself treats an unknown host as no reason, as the table always did. Unifying the two would change one surface while the host call loads, and would mean a DEC, so it was left out.

Checking that it's the same rule: for a loaded host, `runBlocker` is null exactly when `live_runs_allowed && enabled && online`. `live_runs_allowed` is a `boolean`, so that is the old `=== true && enabled && online`. With no host, both sides are false.
