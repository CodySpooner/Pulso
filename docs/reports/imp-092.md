# imp-092 — Import panel: a running import keeps its file against Choose another and a drop

Branch `CodySpooner/imp-092-import-file-guard`, on `origin/main`. This change is web-only. It touches no API, schema, dependency, env file, source, collector, CI or protected path. Recorded as DEC-182, proposed (imp-092). The work does not depend on imp-089, imp-081 or imp-080, and none of them is merged here.

## Reproduction (imp-089 "Found, not fixed", P2)
The finding came from code reading and is **confirmed**. **Choose another…** and a dropped file both call `check()`, which calls `commit.reset()`. TanStack Query's `reset()` detaches the panel from the running mutation, so the mutation's `onSuccess` never runs.

**Method:** a throwaway Playwright spec on `main`'s `import-panel.tsx` (fixtures, E2E auth bypass). The fixture commit route was held pending on a promise. Mid-import, `other.csv` was supplied by three paths: Enter on the focused Choose another… (then the file chooser), a pointer click on it, and a dispatched `drop` on the zone. The commit was then released. All three paths gave the same result:

| Path | Status during import | Status after the commit finished | Open runs | Previews | Commits | `/sources` refetch |
|---|---|---|---|---|---|---|
| keyboard Choose another… | "3 valid rows · 1 invalid row" (other.csv) | same; no outcome | 0 | 2 | 1 | none |
| pointer Choose another… | same | same; no outcome | 0 | 2 | 1 | none |
| drop | same | same; no outcome | 0 | 2 | 1 | none |

The server imported `rates.csv` (one commit, run #501 in the fixture). The panel never showed the outcome, never offered Open runs and never refreshed the source data. It showed a second check, of the new file. The throwaway spec was not committed.

## The fix
All changes are in `apps/web/src/components/data-health/import-panel.tsx` (+14 / −3):
- **`check()`, the shared file entry:** `if (commit.isPending && next !== file) return;`. Every caller that replaces the file goes through this one line: the picker's `input` change, a drop, and a preview Retry. A preview Retry can't occur mid-import, but the guard covers it anyway.
  - **Why `next !== file`:** on `main`, the Source select's change calls `commit.reset()` and then `check(file, newKey)` with the *same* file. A bare `commit.isPending` guard would skip that re-check and leave the old source's preview under the new source. Source selection belongs to imp-089, so the guard refuses only a different `File`, and the select behaves exactly as on `main`.
- **Choose another…:**
  - It is `aria-disabled` while the commit is pending, and its `onClick` opens no picker. Click, Enter and Space all go through `onClick`.
  - It stays in the tab order. Its text dims to `--subtle-foreground`, with `aria-disabled:opacity-100` overriding the Button's `opacity-50`, so the focus ring keeps full strength.
  - `cursor-not-allowed` matches the Import button's lock.
- **Drop zone:**
  - While importing, `dragover` sets `dropEffect = "none"` (a no-drop cursor) and skips the brand highlight, so the zone doesn't invite a drop it would refuse.
  - `preventDefault()` stays, so a file dropped mid-import never opens in the tab.
- **After success or failure:** `commit.isPending` is false, and choosing or dropping a file checks it as before.

**Leftover finding (backlog row, P3):** the Import button's own aria-disabled state ("Importing…") uses the Button default `opacity-50`. That also fades its focus ring when a keyboard user has just pressed Enter on it; imp-089 measured the same utility at 1.93:1 in light. Two fixes would work: the same token dim, or a Button-level `aria-disabled` treatment without opacity. The button sits in `PreviewResult`, the preview area imp-080 is changing, so it was not touched here.
