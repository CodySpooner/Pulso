## Docs check (SPEC §4.2), 2026-10-25

The Open Platform pages render with JavaScript. They were read through the docs site's own JSON (`/handler/share/doc/getDocDetail.json`, `/handler/share/apidoc/getApi.json`), a local headless Chromium, and the official Java SDK source behind the API page's public SDK link. The API gateway was never called. URLs, dates and rules are in `docs/DATA_SOURCES.md` (AliExpress).
- **Terms:** the API Use Agreement still reads "Updated on: 25 Jan, 2022", unchanged since 2026-10-22, so the adapter design stands, still off.
- **Signing** (docs 1366, 1367): sort the parameters, join name+value, prefix the path for System Interfaces only, then upper-case hex HMAC-SHA256 keyed with the App Secret. Both published worked examples reproduce, with openssl and in the test.
- **Two doc inconsistencies:**
  - The Business sample signs a different `method` from the one it lists. The test uses the signed one.
  - `shipping_fee_cent` is described as cents, but its example holds major units. The parser checks it against the formatted fee (DEC-283 g).
- **Undocumented:** individual throttle and auth error codes. Only the throttle message and the `SYSTEM`/`ISV`/`ISP` types are documented, so the classifier keys on those plus the HTTP status.

**Acceptance:**
- **AE-1:**
  - `test_parse_product_and_freight_into_usd_minor_units` covers wrapped and bare lists, not-found and no-delivery answers.
  - `test_parse_fails_closed_on_other_currencies_and_a_cents_fee` covers a non-USD SKU and a cents fee.
  - `test_sign_matches_the_documented_worked_examples` checks both published samples, with keys deliberately unsorted, plus `sign` and blank values excluded.
  - `test_form_signs_exactly_the_parameters_it_sends` checks the exact sent parameter set; the secret never appears in the body.
  - The docs check date and URLs are in `docs/DATA_SOURCES.md`.
- **AE-2:** `test_lookup_caches_24h_and_writes_nothing_durable` runs on SQLite and on Postgres.
  - A product+freight lookup through a fake transport leaves the row count of every table unchanged: every migrated table on Postgres, `raw_payloads` included.
  - The S3 client is never made, so there are zero puts, and no log record carries the payload.
  - The TTL is 86,400 s. At +24 h −1 s the answer comes from the cache with no transport call; at +24 h the key has expired and the lookup calls again.
- **Block:** `test_consecutive_throttles_disable_once_and_honour_retry_after`.
  - The sequence is 4 throttles, a success (which resets the count), then 5 throttles. The fifth consecutive one disables the source with exactly one `SourceEvent`, and later lookups make no call.
  - `Retry-After: 120` sets `retry_not_before` to +120 s, and a lookup at +119 s makes no call.
  - The documented "ban will last 1 seconds" also sets `retry_not_before`; the loop steps 2 s past it.
- **Also tested:** `test_revoked_auth_disables_at_once_and_errors_do_not_count` checks that a `SYSTEM` error disables at once with one event, while an `ISP` error doesn't count. `test_off_unconfigured_or_live_guarded_lookups_make_no_call` covers flag off, a missing token, the worktree live guard, the daily cap, and non-digit IDs.
