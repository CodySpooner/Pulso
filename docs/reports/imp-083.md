# imp-083 — sidebar keyboard focus stays whole at the scroll edges

Claude worker, Orca task `task_50a6604fc2a1`, dispatch `ctx_8902e61c85b4`. Branch `CodySpooner/imp-083-sidebar-focus`, rebased on `origin/main` `08b1d6d`. Not pushed or merged. This fixes aud-011 **B11-02** (evidence in `docs/reports/aud-011.md` on `CodySpooner/aud-011-visual-polish`; I read it there and did not merge that branch). DEC-178 is unused: the fix is plain CSS and needs no new decision.

## Cause

The nav scrolls inside a box (`shell/sidebar.tsx:50`) that had no top padding and a 48px bottom fade (`mask-b-from-[calc(100%-3rem)]`), with `pb-12` of content padding below the list. The focus ring (2px outline + 2px offset) reaches 4px outside each link. As a result:

- the first link's ring touched the box's clip edge and lost its top 4px;
- Tab scrolls a partly hidden link only as far as the box edge. With no `scroll-padding`, focus stopped inside the fade going down and against the top clip edge going back up;
- at the end of the scroll, the last link's ring still sat 4px inside the fade, because `pb-12` covers only the fade and not the ring.

## Fix

One class string in `apps/web/src/components/shell/sidebar.tsx`:

```diff
- min-h-0 flex-1 overflow-y-auto px-2 pb-12 …
+ min-h-0 flex-1 scroll-pt-1 scroll-pb-13 overflow-y-auto px-2 pt-1 pb-13 …
```

- `pt-1` (4px) gives the first link's ring room inside the clip edge.
- `scroll-pt-1` (4px) and `scroll-pb-13` (52px = the 48px fade + the 4px ring) make Tab and Shift+Tab stop each link with its whole ring clear of the top edge and above the fade. Chrome applies scroll-padding to focus scrolling, which the e2e confirms.
- `pb-13` lets the last link scroll that far.

The fade, the rail, the tooltips, the active pill and the nav order are unchanged. The only visible change is that the list starts 4px lower. There's no JavaScript scroll controller, and no change to dependencies, the API, env files, protected paths, sources, collectors or compliance.

|---|---|---|
| 1440×900 | **6 / 40** each | **0 / 40** each |
| 1440×700 | **9 / 40** each | **0 / 40** each |
| 1024×700 (56px rail) | **7 / 40** each | **0 / 40** each |

At 1440×900 the Tab walk down failed on 3 of 20 links before the fix: Daily Pulse (top 4px clipped), Profit (ring 33px into the fade) and UI gallery (ring 4px into the fade, about 92% opacity). aud-011 counted 2 of 20 because it didn't count UI gallery's 4px. The walk back up also clipped Seasonality and Daily Pulse at the top.

**Probed stops after the fix** (both themes give identical numbers):

| Stop | 1440×900 | 1440×700 |
|---|---|---|
| First (Daily Pulse), from the top | ring 0px clipped (ring top on the clip edge; the link starts 4px down); 100% opacity | same |

| Last (UI gallery) | ring bottom exactly at the fade start (0px inside); 100% | same, box at 479px (max scroll) |
| Back to first with Shift+Tab | box at 0; ring 0px clipped | same |

The scroll box is 707px tall at 900 and 507px at 700. The content is 986px tall, so the list scrolls at both heights.
