## What was built

**API: `GET /v1/products/{id}/series`** (operation `get_product_series`)
- Behind `current_principal`, like `GET /v1/products/{id}`. It reads global market data.
- Query: `range=7d|30d|90d|all` (default `90d`) and `metrics=` a comma list. Unknown metrics return 422 `invalid_metrics`, and an unknown id returns 404.
- A merged id answers 308 to `../{survivor}/series` with the query kept.
- Each series is either a `Series` or a NoSource `MissingSeries {metric, value: null, reason}`. A `Series` is `{metric, unit, source, source_name, method, as_of, stale, points[{day, value, high, as_of}], gaps[{day, status}]}`.
- **price** and **store_count** come from `listing_snapshots` of the product's store listings.
  - A point exists only on a UTC day the source's `source_daily_coverage` reads `success` or `partial`.
  - Each listing carries its newest snapshot from before *d* + 1 00:00Z, because snapshots are change-only. A listing counts until its `delisted_at`.
  - price is the lowest to highest USD minor price; store_count is the number of distinct stores.
- **velocity_js** (A, `shp_inv`) and **velocity_bumps** (B, `shp_bump`) come from `product_daily_features` only, using the newest `feature_version` per day. They are NoSource when there are no rows.
- **search** is NoSource. `search_trends` is keyword-level, and the product↔keyword link is Phase 3. **ads** is always NoSource in Phase 2.
- **gaps** are the coverage days marked `gap` or `failed` that have no point. Other days without a point have no band; the line just breaks. Nothing is interpolated or filled.

**Web: the Trends tab** (`?tab=trends`)
- `trends.tsx`: the toolbar, pane headers, states and no-source rows.
- `trends-chart.tsx`: the ECharts canvas, loaded with `next/dynamic` and `ssr: false`.
- `trends-model.ts`: the pure helpers.
- `lib/charts/theme.ts`: the one chart theme, read from the CSS tokens at render and again on a theme change.
- **Panes:**
  - Order velocity: A solid; B dashed and named a lower bound. The families are never summed.
  - Retail price: a low–high band.
  - Stores selling it.
  - All panes share one canvas with linked UTC time axes, one crosshair and one tooltip.
- **Range:** 7D/30D/90D/All with a sliding thumb (`spring.snappy`). It moves a client-side window over one `range=all` response, so it never refetches. All starts at the real first date.
- **Pane toggles:** one chip per pane that has data. Range and panes are kept in the URL (`range`, `overlay`), with defaults left out.
- **Gap days:** a hatched band (canvas pattern from `--muted-foreground`) across the whole UTC day on every pane, with a legend entry: "Collection gap · N days, no data".
- **Source and as of:**
  - Every pane header shows the source, the as of, and the stale cue (icon and text) when stale.
  - Every tooltip row shows the value plus source · as of, or "No data · collection gap / every run failed", or "Not observed · no capture that day".
- **Keyboard:** Tab reaches the range buttons, the pane chips and then the chart. On the chart, ←/→ step a day, Home/End jump, and Esc hides the tooltip. An `aria-live` line reads the day's rows. The chart's `aria-label` summarises the window, the latest values and the number of gap days.
- **Motion:** the chart animates on its first draw only (400 ms `cubicOut`). Range and pane changes redraw instantly. Under reduced motion nothing animates.
- **States:**
  - pane skeletons;
  - error with cause, error ID and Retry;
  - a stale line when a refresh fails;
  - no history ("No history for this product yet", with Open Data Health);
  - short history (fewer than 7 days);
  - "No point in this range" on a pane;
  - "Every pane is off";
  - no source yet: Search interest and Ad count, plus "Insufficient signal" for demand. Each is a row with its reason, never a zero line.

## Acceptance checks

### (a) Gap days: the API returns them, and Playwright sees shaded bands
- API: `test_points_only_on_collected_days_and_gaps_from_coverage` sets coverage to `success` on days −5, −4, −2 and −1, `gap` on −3 and `failed` on 0, and leaves −6 with no record. It asserts the gaps are exactly −3 (`gap`) and 0 (`failed`) with no point on either, and that −4 carries −5's unchanged snapshots. `test_velocity_reads_the_newest_feature_version_and_no_gaps` covers the case where there are no gaps (`gaps == []`).
- Playwright (`trends.spec.ts`, "gap days from coverage render as hatched bands"):
  - It reads the canvas pixels over each gap day in the price pane, and more than 90 % are painted. A day with no record at all paints under 30 %.
  - The legend reads "Collection gap · 3 days, no data", and the chart's `aria-label` counts the 3 gap days.

### (b) No point on an unobserved day
- API: days −6 (no record), −3 (gap) and 0 (failed) have no point, even though listings exist on them. A snapshot captured at exactly day −3 00:00Z, which is day −4's cutoff, doesn't count on day −4. It counts first on −2, because −3 is a gap. Every point's `as_of` is before its day + 1 00:00Z. In the velocity test, a feature day with no `velocity_7d` has no point.
- Mutating the cutoff to `<=`, or reading `gap` as observed, makes a test fail. Both mutations were reverted.
- Vitest: `align` leaves unobserved days null, and `gapBands` merges consecutive gap days.

### (c) States
Covered by Playwright and by screenshots of each: loading, error, no history, short history, stale, no source yet and gap tooltip. "No point in this range" and "every pane off" are covered in code and by the pane toggle test.
