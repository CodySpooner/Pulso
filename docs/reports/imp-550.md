## Cause

- `dated_economics()` built Pulse's dated copy of `workspace_product_economics` from migration 0014's `in_stock_first()`.

**How `dated_economics()` finds the live view's text.** This follows the lead's note after dispatch; it was the spec's preferred option.

1. It walks Alembic's revision graph from the head: `ScriptDirectory(pulso_core/migrations).walk_revisions()`.
2. It takes the first revision that defines `previous_view()`. Every view revision has one: 0014, 0023, and imp-545's 0024.
3. It runs that revision's `upgrade()` against a stand-in `op` that records the SQL, on Alembic's private copy of the module, and takes the one statement it executes.
4. A second statement, or any other `op` call, fails loudly.

**The overlap with imp-545:**

## Tests

- **Guard:** `test_the_dated_view_is_the_live_view_text_but_for_the_cutoff_rewrites`.
  - It undoes the three rewrites on `dated_economics()`, asserts that no `:cutoff`, `:workspace_id` or `:ids` is left, and creates a temp view from the result.
  - It then compares that view's `pg_get_viewdef(…, true)` with the live view's: every `ORDER BY` clause first (the brief's check), then the whole text. Postgres normalises both sides, so the test needs no whitespace or cast handling.
  - It catches a wrong revision, any view change Pulse misses (not only the pick), and any new rewrite it doesn't undo.
- **Probe:** `test_with_duty_unset_the_margin_costs_the_live_views_cheapest_listing`, XR-67's case.
  - A workspace with duty unset, fees 2.9% + 30¢, returns 5%.
  - Two products, each with a $29.99 store price and two CJ listings with $4.10 US freight: $20.00, created first (the lower id), and $5.00.
  - In "Cheap one moves", the $5.00 listing goes to $6.00 on D. In "Dear", the $20.00 listing goes to $21.00 on D.
  - The test asserts that the live view picks the $5.00 listing for both products. It then asserts that the Pulse margins section for D holds exactly one item: "Cheap one moves", 6075 → 5742 bps, on the $5.00 listing, `duty_not_set` true.
