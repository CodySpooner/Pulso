### API as built

- `GET /v1/tests?stage=&cursor=&limit=` → `{items, next_cursor, kill_reasons}`. Newest first, an integer cursor, `limit` ≤ 100 (default 50). `kill_reasons` counts every killed test in the workspace by reason, whatever the filter or page.
- `POST /v1/tests {product_id, stage?, started_on?, ended_on?, ad_spend_minor?, revenue_minor?, orders?, notes?, kill_reason?, scenario?}` → 201. A second open test (Idea, Researching or Testing) for the same product gets 409 `conflict`. An unknown product gets 404, a merged one 409 `merged`.
- `GET /v1/tests/{id}` and `PATCH /v1/tests/{id}` (same fields as POST, minus `product_id`). Another workspace's id gets 404.
- Every test returns `cpa_minor` (= `ad_spend_minor / orders`, half-even, null with 0 orders) and `roas` (= `revenue_minor / ad_spend_minor`, null with 0 spend), both computed on read.
- **Stage moves:**
  - Entering Testing sets `started_on` and, the first time only, stores `start_snapshot`: the Profit calc for the optional `scenario` (default scenario without one), plus `captured_at`.
  - Entering Winner or Killed sets `ended_on`.
  - Reopening clears `ended_on`, and the kill reason when leaving Killed.
- **422 codes:** `kill_reason` (Killed without one, or one on another stage), `date_order`, and `snapshot_locked` (a `scenario` once the snapshot exists). A body field `start_snapshot`, `cpa_minor` or `currency` is a validation 422 (`extra="forbid"`).

**Acceptance, as tested:**
- **CPA and ROAS** match hand calculations:
  - $200.00 / 3 orders = $66.67;
  - $48.65 / 2 = $24.32 (half-even, where half-up would give $24.33);
  - ROAS $259.99 / $200.00 = 1.29995;
  - null on 0 orders and on 0 spend.
- **Kill reason:** Killed without a reason is 422 `kill_reason`, through both PATCH and POST.
- **Start snapshot:**
  - It holds the chosen variant, the freight quote row id, 20% duty, 2.9% + $0.30 fees and an $18.00 CPA estimate.
  - Its break-even CPA is $22.53 = $39.99 − ($10.00 + $4.00 + $2.00) − ($1.16 + $0.30).
  - It is unchanged after a settings fee change, a new supplier price, a metrics PATCH and a Testing → Researching → Testing round trip.
  - PATCH can't send a snapshot or a new scenario, and a SQL `UPDATE` is refused by the trigger.
  - Without a scenario, an incomplete default calc is stored with `missing`.
- **Kill-reason counts** equal the killed tests on every page and under the `stage` filter.
- **Isolation:** workspace B gets 404 on A's test and an empty list with `{}` counts, and can open its own test on the same product. `test_workspace_money_and_utc_contract` covers the table's `workspace_id NOT NULL` + index, `_minor` BIGINT + `currency CHAR(3)`, and tz-aware timestamps.

**Mutations:** 14 one-line mutations to the router and the migration, applied one at a time. Each fails a test:
- CPA as floor or as half-up;
- the kill-reason check dropped;
- kill reason or `ended_on` not cleared on reopening;
- re-snapshot on every entry to Testing;
- the trigger's `RAISE` commented out;
- counts not scoped to the workspace;
- the stage filter dropped;
- the owner check dropped;
- ascending order;
- the date-order check dropped;
- `started_on` not set;
- ROAS dividing by `spend or 1`.

The first run left "CPA as floor" alive: the hand-calc numbers rounded the same both ways. The $200.00 / 3 case now kills it.
