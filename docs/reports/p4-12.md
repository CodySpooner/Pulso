## Behaviour

**Tables (DEC-319 a):**
- `boards`:
  - columns `id` uuid, `workspace_id`, `name` varchar(80), `description` text, `position` int (stored, default 0, not read yet), `archived_at`, `created_at`, `updated_at`;
  - UNIQUE `(workspace_id, name)`, archived boards included;
  - UNIQUE `(workspace_id, id)`, which the items' foreign key needs.
- `board_items`:
  - columns `workspace_id`, `board_id`, `product_id`, `position` int, `note` text, `added_at`;
  - primary key `(board_id, product_id)`;
  - foreign key `(workspace_id, board_id)` → `boards (workspace_id, id)` ON DELETE CASCADE.
- Both tables have `workspace_id` NOT NULL and indexed. The downgrade refuses while any board exists.

**Endpoints.** The operation id is the function name. Every write bumps the board's `updated_at`; a request refused before it saves anything bumps nothing.

| Endpoint | Operation id | Behaviour |
|---|---|---|
| `GET /v1/boards?archived=` | `list_boards` | Active boards (default) or archived ones, newest `updated_at` first, each with `item_count`. Not paged |
| `POST /v1/boards {name, description?}` | `create_board` | 201. A duplicate name, archived boards included, is a 409 `conflict`; a blank, too-long or extra field is a 422 |
| `PATCH /v1/boards/{id} {name?, description?}` | `update_board` | Rename; `description: null` clears it. A duplicate name is a 409 |
| `POST /v1/boards/{id}/archive` | `archive_board` | Sets `archived_at`; again keeps the first one |
| `POST /v1/boards/{id}/unarchive` | `unarchive_board` | Clears `archived_at` |
| `DELETE /v1/boards/{id}` | `delete_board` | Returns the board as it was; its cards go with it (the cascade). Products and tests stay |
| `GET /v1/boards/{id}/items?cursor=&limit=` | `list_board_items` | `product_id`, `name`, `image_url`, `position`, `note`, `added_at`, in board order with `product_id` breaking ties. Cursor `[position, product_id]`; `limit` 1–100, default 50. A bad cursor is a 422 `invalid_cursor` |
| `POST /v1/boards/{id}/items {product_ids[]}` | `add_board_items` | 1–100 ids, appended after the last card in the order given. A merged product adds its survivor, deduplicated. Returns `{added, skipped}`; skipped were already on the board and keep their place and note. An unknown id is a 404, and nothing is added |
| `PATCH /v1/boards/{id}/items/{product_id} {position?, note?}` | `update_board_item` | Moves the card to a 0-based `position` (past the end means last) and renumbers the board 0…n−1; `note: null` clears the note. Returns the card. A product not on the board is a 404 |
| `DELETE /v1/boards/{id}/items/{product_id}` | `remove_board_item` | Idempotent. The other cards keep their order (a gap until the next move). Returns the board |
| `POST /v1/boards/{id}/items/send-to-testing {product_ids[]}` | `send_board_items_to_testing` | One `testing.create_test` call per survivor without an open test (Idea, Researching, Testing). Returns `{created: [tests], skipped: [product ids]}`. A product whose tests all ended gets a new Idea test |

**Isolation:**
- Another workspace's board answers 404 `not_found` on every `/v1/boards/{id}…` route.
- The database refuses a card whose workspace differs from its board's.
