## What changed

- `providers/providers.tsx`: `mutations: { networkMode: "always" }`. Queries keep TanStack's default `"online"`: offline they pause, and on reconnect they refetch (reads are safe, and the banner explains why nothing updates). The config is exported for its unit test.
- `shell/offline-banner.tsx` (new), placed in `shell/app-shell.tsx` under the top bar. `useOnline()` reads TanStack's `onlineManager`, the same signal that pauses queries, so the banner and the pausing always agree. Copy (UI States, Offline (browser)): "**You're offline.** Showing data as of Oct 22, 14:00 UTC. Refresh and actions are off until you reconnect." The time is the oldest last fetch among the active queries (nothing lands while offline). If nothing has loaded yet, the as-of clause is left out. Same warning strip tokens as imp-132's stale line, layered over the page background so a sticky banner on a phone hides what scrolls under it.
- `data-health/atoms.tsx`: `TapTooltip` is inert without a hint. A control whose reason comes and goes (offline) stays the same element, so a focused switch or button keeps focus when the connection drops.
- `data-health/data-health.tsx`, `sources-table.tsx`, `import-panel.tsx`: the offline reason per control (below). `actionFailure` names the connection, not the API, when an action fails while offline.
- `ui/switch.tsx`: the track keys on `aria-checked` instead of `data-state`. A Radix tooltip trigger wrapping the switch replaces its `data-state` with the tooltip's ("closed"), which turned checked tracks grey. Online the switch looks exactly as before.
- Locked Refresh, Run now and switches dim with tokens, not opacity (DEC-185's rule), so the focus ring keeps 3:1.

## Leftovers (proposed backlog rows, not changed here)

1. **P3, Claude, `import-panel.tsx`:** a check or import already in flight when the connection drops, or started by the Source select offline, fails with the transport copy "The API didn't answer while checking the file. When it runs on your PC, check that the PC is on." The banner says offline, but the line blames the API. Capture `onlineManager.isOnline()` at failure (as `actionFailure` now does) and say "You're offline. Retry once you reconnect."
2. **P3, Claude, `atoms.tsx`:** the offline hint is one generic sentence ("Reconnect to use this."). Naming the action ("Reconnect to refresh.", "Reconnect to change CJ Dropshipping.") would read better; it needs a hint per call site.
3. **P3, Claude, `atoms.tsx` `TapTooltip`:** a tooltip opened by a click or tap doesn't close another open TapTooltip (it sets `open` directly, so Radix's one-open-tooltip event never fires). Two reasons can show at once after a tap on one control while another has keyboard focus. Pre-existing (imp-073).
4. **P3, Claude, Radix tooltip:** Radix closes a tooltip when an ancestor of its trigger scrolls. Tabbing to a control scrolled out of view scrolls `main`, which closes the reason the focus just opened. Pre-existing for every TapTooltip; the spec scrolls first.
5. **P3, Claude, `atoms.tsx`:** Retry on a stale line or panel error, pressed offline, pauses silently until reconnect (queries keep `networkMode: "online"`). Not in this brief's control list; the banner explains it, and the refetch on reconnect is a read.
