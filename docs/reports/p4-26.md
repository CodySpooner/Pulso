- **XR-66 (p4-20): when duty isn't set, Opportunity costs the product's lowest-id supplier listing, not its best one. A product can then be capped at 25 for "margin below your floor" because of a supplier nobody would use.**
  - **Where:**
    - `packages/ml/src/pulso_ml/scores/opportunity.py:73-88`: `margin_of()` re-costs, at duty 0, whichever listing the economics row picked.
    - `packages/core/src/pulso_core/migrations/versions/0010_workspace_product_economics.py:357-358`, with 0014's `stock.sold_out` edit: the view's pick orders by `cost.complete DESC, cost.margin_minor DESC NULLS LAST, cardinality(cost.missing), l.id`.
    - While `duty_default_bps` is NULL, every candidate is incomplete with a NULL margin, so `l.id` breaks the tie.
    - `packages/core/src/pulso_core/landed_cost_loader.py:296-299`: `calculate()` has the same rule ("the fewest missing inputs, then the lowest id").
    - Before p4-20 that pick never produced a margin (R-16), so which listing it named didn't matter. `margin_of()` now scores it.
  - **Failure (probe through `GET /v1/products/{id}/scores`, `b1a3e93`):**
    - **Setup:** a $29.99 store price and two CJ listings with $4.10 freight each: $20.00 (created first, so the lower id) and $5.00. Fees are 2.9% + 30¢, and returns 5%.
    - **Duty unset** (the default for every new workspace): the view picks the $20 listing. Margin is 0.1074, and Opportunity is **25.0, "margin below your floor"**.
    - **Duty set to 0:** the view picks the $5 listing. Margin is 0.6075, and Opportunity is **69.8**.
    - **The same two listings created cheapest first:** 69.8 either way.
    - DEC-331 (b) says duty not set is costed at duty 0, so both cases should score 69.8, and only confidence should differ (0.7 against 0.9).
  - **Rule:**
    - DEC-331 (b): the margin is that of the row behind "Discover's and the Overview's best margin".
    - The vault Opportunity Score note: Margin is the "contribution margin … from the workspace's landed cost", and "duty not set" lowers confidence, not the margin.
    - R-16's `best()`: the best supplier is the highest margin.
  - **Why medium, not high:**
    - The `landed_cost()` arithmetic is right: the USD and CNY parity probes match the view at duty 0 to the basis point. The pick is what's wrong.
    - It's computed per read and never stored, so no history is wrong.
    - No web surface reads `/scores` yet (grep: no caller outside `schema.d.ts`).
    - It is realistic, though: duty is NULL by default, and a product matched to two or more supplier listings is ordinary.
  - **Fix:**
    - Rank the candidates whose only gap is `duty_not_set` by their duty-0 cost. Add `cost.goods_minor + cost.freight_minor NULLS LAST` after `cardinality(cost.missing)` in the view's ORDER BY.
      - It's a new view migration in 0014's pattern: read the previous view and replace one line.
      - p4-24 holds 0022 now, so put it on the head at merge time.
    - Use the same key in `calculate()`'s fallback: `(len(missing), goods + freight, id)`.
    - Price, fees, returns and the customs fee are the same for every listing of a product in a workspace, so the lowest goods + freight is the best margin at duty 0. With duty set, nothing changes: complete rows still rank by margin.
    - Add a golden vector to `landed_cost_vectors.json` (the dearer listing created first, duty unset).
    - Add an API test: Opportunity with duty unset equals the duty-0 workspace's value, except for confidence.
    - Note the tie-break in DEC-331 (b) and DEC-265.
    - **The other option,** which needs no migration, is `calculate(..., overrides={"duty_bps": 0})` in the endpoint whenever duty is the only gap. It loses the set-based read that DEC-331 keeps for the Screener.
