## What changed

- **One action per withheld state** (`apps/web/src/app/(app)/products/[id]/overview-model.ts`, `marginFix`). Before this change, 0 withheld margins had a next action. Now every withheld state has exactly one:

  | Withheld state (card label · `missing`) | Action | Lands on |
  |---|---|---|
  | "Duty not set" · includes `duty_not_set` (wins even beside other gaps: it is the card's amber label) | **Set duty** (link) | `/settings#duty`: "Set a rate" chosen, Default duty rate box focused |
  | "No source yet" · `[]` (no workspace settings row, DEC-299 b) | **Open Settings** (link) | `/settings`, whose first read creates the row |
  | "No source yet" · any of `supplier_cost_missing`, `freight_missing`, `freight_variant_mismatch` (beats a missing price: without a supplier, Profit shows only "No supplier cost yet") | **Open Suppliers** | Suppliers tab, focus on its tab |
  | "No source yet" · `price_missing` (no supplier gap) | **Enter a price** | Profit tab, focus on its tab |
  | "No source yet" · `fx_missing` or `amount_out_of_range` only | **Open Profit** | Profit tab, focus on its tab |

- **The card** (`overview.tsx`, `stat-card.tsx`). `StatCard` has a new optional `action` slot, rendered after the reason line. The action is the same ghost chevron button that "Where it appears" uses, with its text aligned to the card's. Tab actions go through the page's `goTo`, so focus lands on the tab they open. The card's existing states, the "never 0" rule (DEC-040) and the as-of line are unchanged. A complete margin has no action.
- **The Settings anchor** (`settings-form.tsx`). The `#duty` section id already existed. On arrival at `/settings#duty`, the form's first draft has "Set a rate" chosen, and the empty rate box takes focus once. This matches what the page's own "Set duty" check does. The form then reads "Unsaved changes" until Save or Reset, as it does after that check. A later refetch never reopens the rate, and an already-set duty is just focused. The draft is built in the existing adjust-during-render sync because the React Compiler lint (`react-hooks/set-state-in-effect`) rejects a setState in an effect.
- **DEC-309** records these defaults.

**Clicks.** Each withheld state reaches its fix in **1 click** (or Tab + Enter) from the Overview. To set duty from the Overview takes 1 click, then typing the rate, then Ctrl/⌘+S or Save: 2 clicks in all, with no scrolling and no extra click to open the rate.
