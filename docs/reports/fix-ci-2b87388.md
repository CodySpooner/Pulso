- **Run:** Claude worker on branch `CodySpooner/fix-ci-2b87388`, Orca task `task_d04ed1cab62b`, dispatch `ctx_9965e2aaef26`. Nothing was pushed or merged.
- **Target:** CI run 40222458864 on `2b87388`, e2e job: `e2e/methodology/methodology.spec.ts:50` "no horizontal page scroll at 375px" (it failed on retry too). `fedca60` (run 40224875341) carries the same layout, so it is expected to fail the same way.
- **Scope:** two class changes in `methodology.tsx`, one new e2e test, two screenshots and this report. No dependency, token, `methodology.json` or API change. No data source was contacted.
- **Decision:** none (DEC-327 unused).

## Root cause

The overflowing elements were the **Saturation inputs** and **Trend Score v0 inputs** tables (`<table aria-label="… inputs">`, rendered by the shared `Rows`). `Rows` sets `whitespace-nowrap` on every value cell, so a type such as `Mapping[UUID, Sequence[int]]` (28 mono characters, first shipped with Saturation in p4-11, again in p4-14's Trend) counts its full width toward the column's minimum. A table never shrinks below its columns' minimum, so at 375px those tables were 341px wide inside a 309px card body. They spilled 32px past the card and ended at x = 374, 1px inside the viewport with Geist Mono on Windows. CI's Linux font rasterising pushed that last pixel past 375, so `scrollWidth > innerWidth`. That's why the test passes locally and fails deterministically on CI. The Explanation and Component fields tables overflowed their cards by about 1px the same way (`tuple[Component, ...]`, `AwareDatetime | None`), which the page-level check couldn't see.

Two things the brief suspected weren't the cause:
- **The 64-hex fingerprint** (`config_digest`) renders only in a `title` attribute, so it takes no layout space.
- **The module path** (`pulso_ml.scores.saturation.saturation_scores`, the `Sub` note) didn't overflow. It was cut off with an ellipsis (`truncate`) at 375px, which loses data, so it now wraps instead.

Measured at 375px (`getBoundingClientRect` against the parent's `clientWidth`):

| Table | Before | After |
|---|---|---|
| Saturation inputs | 341.0 / 309 | 309.0 / 309 |
| Trend Score v0 inputs | 341.0 / 309 | 309.0 / 309 |
| Explanation fields | 310.2 / 309 | 309.0 / 309 |
| Component fields | 310.2 / 309 | 309.0 / 309 |
| Every other table | ≤ its box | unchanged |

## What changed

| File | Change |
|---|---|
| `apps/web/src/app/(app)/methodology/methodology.tsx` | `typed()` (every Inputs and contract field table) puts `max-sm:whitespace-normal` on the type, so below `sm` a type wraps at its own spaces. The cell keeps `whitespace-nowrap`, so a config value (`002-73de55ab0c1d`, `−0.2231`) never breaks. The `Sub` note goes from `truncate` to `break-all` (the repo's idiom for IDs), so the full module path shows. The `Rows` comment says why |
| `apps/web/e2e/methodology/methodology.spec.ts` | New test "at 375px every table and code path wraps inside its card": every `main table` and every `Sub` module path must fit its parent box and must not be clipped. It also checks that the longest built-score token, `pulso_ml.scores.saturation.saturation_scores`, is visible. It failed before the fix (5 spills: the Saturation path plus the 4 tables above) and passes after. The existing 375px test is unchanged |
| `docs/screenshots/fix-ci-2b87388/` | `saturation-inputs-375-dark.png`, `trend-score-inputs-375-dark.png` |

- **Every section is covered:** the fix sits in the shared `typed()`/`Sub` rendering, so every built score (Velocity, Lifecycle, Saturation, Trend and any later one) and the contract tables get it.
- **What the new test catches:** it walks every table on the page. A future score with an unbreakable over-long token fails it on any OS with a named element, not by 1px on Linux only.
- **Desktop is unchanged:** at 640, 1024 and 1440px every value cell and type still computes `white-space: nowrap`, and no module path wraps (checked in the browser). `break-all` only acts when a path doesn't fit, which no longer happens at those widths.
