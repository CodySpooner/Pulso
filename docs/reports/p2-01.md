## DEC-237 in short

- **(a)** OpenCLIP `ViT-B-32` / `laion2b_s34b_b79k` for images and titles: one 512-d space. Changing the model means a migration and a re-embed.
- **(b)** `pgvector` 0.4.2 joins `pulso-core` (free, MIT; brings `numpy`). A mypy override like boto3's, because it has no `py.typed`.
- **(c)** Candidates: one mutable row per pair. The queue index is a plain `(status, score)` btree, read backward for `score DESC` (DEC-158 pattern).
- **(d)** Decisions: one append-only row per affected listing, so membership(listing, t) is the latest row's `to_product_id` before t (R-15). `confidence` was kept because append-only rows can't be backfilled. `reject_append_only_mutation()` is generic for later `scores` and `forecasts`.
- **(e)** Mappings: `category_id` NOT NULL (no row = unmapped); no taxonomy seed (M-6).
- **(f)** Notes and tags use `WorkspaceOwned`.
- **(g)** The features primary key's prefix serves `(product_id, feature_date)`; no extra index.
- **(h)** Duty NULL = "duty not set" and may pass 100%; the customs fee uses the row's `currency` like the other settings money.
- **(i)** Downgrade refuses to drop match decisions, notes, tags, manual mappings or non-default Phase 2 settings.

## Notes for later tasks

- **M-2:** write vectors through `pgvector.sqlalchemy.Vector` (lists or numpy arrays); the column refuses any width but 512. Don't write zero vectors: cosine distance to a zero vector is undefined.
- **M-3 / M-5:** store pairs with the lower listing id as `listing_a_id`. Every change to `listings.product_id` appends one `match_decisions` row per listing in the same transaction.
- **Test databases:** the `db_engine` fixture's search path holds only the test schema. If a test database already has `vector` installed in `public` (for example after an `alembic upgrade` with `DATABASE_URL` on it), 0001's `CREATE EXTENSION IF NOT EXISTS` skips, and 0005's `vector(512)` can't be resolved. CI's fresh `pulso_ci` is fine. Locally, use a fresh database.
