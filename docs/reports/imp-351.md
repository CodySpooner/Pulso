# imp-351: Profit flags an out-of-stock supplier

## The gap

Since imp-289 (DEC-291 c), when no supplier is in stock, the default Profit calc costs the best out-of-stock listing. The response didn't say so, and neither did the tab. A supplier chosen on Suppliers that is sold out looked the same as one in stock.

**Defaults flagged:** before **0** (the response had no stock field). After, **every** out-of-stock costed listing is flagged: the all-out-of-stock default and an explicit sold-out pick both answer `in_stock: false`, and the tab marks both.

## What changed

- **`packages/core/src/pulso_core/landed_cost_loader.py`:** `Calc` gains `in_stock: bool = True`. `calculate()` fills it from `stocked(session, listing)`, imp-289's predicate, once per listing. The in-stock pool now filters on `calc.in_stock`, so the flag and the pick come from the same single read. The pick itself is unchanged. With no listing, the value is `True` (nothing is known to be out of stock).
- **`apps/api/src/pulso_api/routers/profit.py`:** `ProfitCalc.in_stock` is required, additive, and documented in OpenAPI. It is filled from `calc.in_stock`. Suppliers' rows carry it through `cost` (they call `calc_profit`).
- **`pnpm gen:api`:** `apps/api/openapi.json` and `apps/web/src/lib/api/schema.d.ts` regenerated.
- **Profit tab (`profit-tab.tsx`):** the Scenario panel's "Costed from the CJ Dropshipping listing …" line shows the shared `Pill` (tone `negative`, `CircleSlash`, the text "Out of stock") beside the supplier when `in_stock` is false. The default's line ends "with the best complete margin; none is in stock". The marker uses tokens only, and it is text plus an icon, not colour alone. It uses the same tokens and icon as the Suppliers tab's out-of-stock badge.
- **Typed e2e fixtures:**
  - `profit-fixtures.ts`: `complete` gets `in_stock: true`, and there is a new `outOfStock` fixture.
  - `suppliers-fixtures.ts`: the sold-out row's `cost` gets `in_stock: false`. The mock's default calc also now ranks in-stock rows first, as the server has since imp-289. Before, "Let Pulso pick the supplier" landed on the sold-out row's cost, and with the new field that would have shown a marker the real server never would.
  - Every other fixture spreads `complete`.
  - `e2e/products/fixtures.ts` and `suppliers-tab.tsx` are untouched (p3-05).
- **The economics view:** no change (no migration). It already picks the same listing (DEC-265 parity), so Discover agrees on the supplier. The flag lives on the calc answer only (DEC-295 b).
