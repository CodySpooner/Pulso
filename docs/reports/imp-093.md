## Change

At 768–1023px the sidebar, which carries the DH-3 badge, is `display:none`, and there is no tab bar. The attention count therefore sat behind the top bar's **Open menu**. Now that button renders the same `DataHealthNavBadge`:

- `apps/web/src/components/shell/topbar.tsx`: one import, one element, and the label moves from `aria-label="Open menu"` to `<span className="sr-only">Open menu</span>`. An `aria-label` overrides the button's content, so the badge's sr-only wording could never join the name. The badge sits at the top right of the hamburger (`absolute -top-1.5 left-1/2 ml-1 flex`).
- `data-health/nav-badge.tsx`: **unchanged**. The count, the red-only-for-failures pill, the `aria-hidden` digit, the sr-only wording, and the null on loading, error or zero all come from the existing component. It reads the shared `useSources` / `useHost` query keys. The sidebar is always mounted (hidden by CSS), so those queries already ran on every page, and the change adds no request.
- `bottom-bar.tsx`, the sidebar's scrolling and the import panel are untouched.

The accessible name becomes "Open menu, 2 sources need attention". The visible "2" is `aria-hidden`, so the count is announced once. At 768–1023px the sidebar's copy is inside `display:none`. When the sheet opens, the top bar is hidden from assistive tech behind the modal Radix sheet. So a screen reader never meets two counts at once. The button is `md:inline-flex lg:hidden`, so phone (< 768) and desktop (≥ 1024) render exactly as before. `attentionCount`, and with it the blocked / failing / overdue semantics, is untouched. Nothing animates: the badge has no motion, and the button's existing `active:scale` press is unchanged.

No API, schema, dependency, network destination, source, secret, env, CI or protected-path changes. **DEC-183 is unused.** The change reuses the DH-3 rule as written ("a red count" on the Data Health nav item) for the tablet entry point. The sr-only label is noted against the Accessibility note's "aria-label always" wording under Proposals.
