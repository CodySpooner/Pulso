## Semantic conflict found and fixed: imp-030 plan test (DEC-163)

`test_admin_indexes.py` (PostgreSQL only) assumed the old unbounded host read: 2 queries, 2,160 gaps, no Sort or Incremental Sort. On the merged code it failed (`assert 3 == 2`). Plans captured on the pinned image (200,000 fixture gaps, 2,160 open in the window):

| Query | Plan |
|---|---|
| `latest_gap_ends` summary | forward `ix_collection_gaps_open_slot_start`, 2,160 rows, HashAggregate |
| heartbeat | backward `ix_host_heartbeats_at`, 1 row |
| gap page (default 50) | backward `ix_collection_gaps_open_slot_start`, 52 rows (50 + lookahead + one tie probe), Incremental Sort presorted on `slot_start` |
| cursor page, `limit=200` | same index; PostgreSQL derives `slot_start <= cursor` as an index condition; 202 rows, 1 removed by the row filter |

The test now asserts that shape: three queries, a 50-row first page with a cursor, a 4-key summary, no full Sort, and any incremental sort presorted on `slot_start`. Downgrade/upgrade must still return the identical first page. No migration: a composite `(slot_start, id)` partial index would drop the tie sort but is out of scope here. DEC-163 (proposed, imp-074) records this.
