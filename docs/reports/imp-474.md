## Cause

`CatalogAdapter.targets()` sent the tree as `Request(params={"endpoint": "/product/getCategory"})`, which keeps the default `resets_blocks=True`. The framework then set `consecutive_block_count` to 0 on the tree's 200 (`framework/lifecycle.py:165-168`). `cj.collect` reads `previous_blocks` in the hook before each request, so a later body block on `listV2` counted from 0 (`previous_blocks + 1`), and an HTTP 429 counted from 0 as well. The count was 1 after every run, so CJ never disabled.

## Change

| File | Change |

| `packages/sources/src/pulso_sources/cj/__init__.py` (+2 −1) | The tree is sent as `Request(params={"endpoint": "/product/getCategory"}, resets_blocks=False)`, with a comment naming DEC-321a and XR-59 |
| `packages/sources/tests/cj/test_registered_plan.py` (+72 −2) | A `catalog()` helper (a fresh `CatalogAdapter` and `cj.collect` per run, fake HTTP with a status per endpoint) and 5 test cases |
| `docs/DECISIONS.md` (one sentence) | DEC-321a: the tree is sent with `resets_blocks=False`, as DEC-242 (a) does for robots.txt; a blocked tree answer still counts |

The DEC-156 renewal `getCategory` inside `Transport.fetch` is unaffected. It runs inside another request's attempt, and the framework only sees that request's final answer.

**Block handling is unchanged.** An HTTP 403/429/430 tree still increments the count in the framework, since the block check runs before `resets_blocks`. A tree body code (`1600200`, `16900500`) still counts through `cj.collect`'s `previous_blocks + 1`. A successful `listV2` page still resets the count. A run that resolves no names sends only the tree and leaves the count where it was, as robots.txt does.
