## Proof the overview equals Discover

The read is `best_margins()` + `margin_stat()` in `routers/products.py`, shared by Discover and the overview. The tests below ran on `pgvector/pgvector:0.8.7-pg18-trixie`.

- `apps/api/tests/test_profit.py::test_the_overviews_landed_margin_is_discovers_best_margin`: one workspace and three products:
  - a complete margin: 1503 at 5012 bps, the CJ listing;
  - a supplier with no freight quote: `["freight_missing"]`;
  - no supplier at all: `["supplier_cost_missing", "freight_missing"]`.

  For each, the overview's `landed_margin_minor` equals Discover's `best_margin_minor` exactly, all fields included.
- `apps/api/tests/test_profit.py::test_the_overviews_landed_margin_reads_only_the_callers_workspace`: the two-workspace isolation case. One product reads three ways:
  - workspace A (duty 20%, fees): 1503;
  - workspace B (no duty): "Needs a duty rate." `["duty_not_set"]`;
  - a workspace with no settings row: "No workspace settings yet." `[]`.
- `apps/api/tests/test_products.py::test_overview_stats_match_sql_spot_checks` now expects the no-settings `Incomplete` for its random workspace.

**Mutations.** Each was applied alone, and each made a test fail:

1. The overview passes no row to `margin_stat()`.
2. `best_margins()` drops its workspace filter.
3. The overview reads the first workspace's row instead of the caller's.

Results: mutation 1 fails both tests; mutations 2 and 3 each fail the isolation test. After each run the router was restored with `git checkout`.
