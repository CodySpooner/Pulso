# imp-347: the product keywords POST refuses a NUL in its keyword with a field 422 (imp-311-b1)

Improvement Backlog row imp-347, from imp-311's report (b1). p3-02 (KW-1) landed before imp-311, so `POST /v1/products/{id}/keywords` took a plain `str` keyword and wasn't in `test_nul_inputs.py`.
- **Run:** Claude worker on branch `CodySpooner/imp-347-keywords-nonul`, Orca task `task_00c7535206a9`, dispatch `ctx_337180eee4ff`. Nothing was pushed or merged.
- **Decision:** none. This applies DEC-287 as written. The reserved DEC-296 is unused.
- **Not changed:** no migration, flag or dependency. Valid keywords behave as before.

## What changed

| File | Change |
|---|---|
| `apps/api/src/pulso_api/routers/product_keywords.py` | `KeywordIn.keyword` is `Annotated[NoNulStr, StringConstraints(strip_whitespace=True, min_length=1, max_length=100), AfterValidator(searchable)]`. Only the base type changed, from `str`. The constraints merge into one string schema, the same way as `Tag` in `products.py`. |
| `apps/api/tests/test_nul_inputs.py` | A new `TYPED["keyword"]` case. `"a\x00b"` answers a 422 `application/problem+json` with `code` `validation_error` and one error, `(["body", "keyword"], "string_pattern_mismatch")`. The same request with `"a\tb\nc"` still answers 200. |
| `apps/api/openapi.json` | `pnpm gen:api` added one line, `"pattern": "^[^\\x00]*$"` on `KeywordIn.keyword`. `schema.d.ts` came out unchanged, because openapi-typescript doesn't emit patterns. |

**Before the change**, the NUL case was already a 422, but the wrong one. `normalize()` keeps the NUL, and `key()` still finds the letters on each side of it, so the text reached the `INSERT`. The NUL DataError handler then answered `invalid_text`, with no field named. Now FastAPI refuses the NUL before the endpoint runs and names the field.
