## Change

Below 768px the sidebar, with its DH-3 badge, sits behind More, so a phone showed no attention signal until the sheet opened. Now the tab bar's **More** renders the same `DataHealthNavBadge`:

- `apps/web/src/components/shell/bottom-bar.tsx`: one import and one element. The badge is positioned (`absolute top-1 left-1/2 ml-2 flex`) at the top-right of the More icon, inside the button.
- `data-health/nav-badge.tsx`: **unchanged**. The count, the red-only-for-failures pill, the `aria-hidden` digit, the sr-only wording and the null on loading, error or zero all come from the existing component. It reads the shared `useSources`/`useHost` query keys, so it adds no requests.

The accessible name becomes "More, 2 sources need attention". The visible "2" is `aria-hidden`, so the count is announced once. The sidebar is `display:none` below 1024px, and the tab bar is hidden from assistive tech behind the open (modal Radix) sheet, so a screen reader never meets two counts at once. `attentionCount`, and with it the blocked/failing/overdue semantics, is untouched. There is no animation: the badge has none, and the tab bar's `layoutId` indicator is unchanged.

No API, schema, dependency, network destination, source, secret, CI or protected-path changes. No DEC needed: this reuses the DH-3 rule as written in the vault ("a red count" on the Data Health nav item) for the phone entry point. DEC-181 stays unused.
