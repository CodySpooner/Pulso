## Change

Below 768px the sidebar, with its DH-3 badge, sits behind More, so a phone showed no attention signal until the sheet opened. Now the tab bar's **More** renders the same `DataHealthNavBadge`:

- `apps/web/src/components/shell/bottom-bar.tsx`: one import and one element. The badge is positioned (`absolute top-1 left-1/2 ml-2 flex`) at the top-right of the More icon, inside the button.
- `data-health/nav-badge.tsx`: **unchanged**. The count, the red-only-for-failures pill, the `aria-hidden` digit, the sr-only wording and the null on loading, error or zero all come from the existing component. It reads the shared `useSources`/`useHost` query keys, so it adds no requests.

The accessible name becomes "More, 2 sources need attention". The visible "2" is `aria-hidden`, so the count is announced once. The sidebar is `display:none` below 1024px, the top bar's Open menu is `display:none` below 768px, and the tab bar is hidden from assistive tech behind the open (modal Radix) sheet. A screen reader therefore never meets two counts at once. `attentionCount`, and with it the blocked/failing/overdue semantics, is untouched. There is no animation: the badge has none, and the tab bar's `layoutId` indicator is unchanged.

No API, schema, dependency, network destination, source, secret, env, CI or protected-path changes. **DEC-181 stays unused** and DECISIONS is untouched: this reuses the DH-3 rule as written in the vault ("a red count" on the Data Health nav item) for the phone entry point.

## Integration with imp-093 (tablet Open menu, merged via imp-099)

The 18:00Z trial merge conflicted only in `apps/web/e2e/data-health/data-health.spec.ts`: main's imp-069 scroll-cue test and imp-091's More tests were added at the same spot in the phone block. `bottom-bar.tsx` merged cleanly, since imp-093 changed only `topbar.tsx`.

- **One attention-count source.** The phone More, the tablet Open menu, the sidebar item and the sheet's Data Health link all render the one `DataHealthNavBadge` → `attentionCount(useSources, useHost)`. No second component, count or query was added.
- **One naming pattern.** Each control's own label text ("More", visible; "Open menu", sr-only, imp-093) is followed by the badge's sr-only ", N sources need attention". The names are "More, 2 sources need attention" and "Open menu, 2 sources need attention". Neither control has an `aria-label` that would override the badge wording.
- **Breakpoints never overlap.** The tab bar is `md:hidden` (below 768), Open menu is `md:inline-flex lg:hidden` (768–1023) and the sidebar is `lg` and up. Exactly one count is visible at any width.
- **Tests.** Both sets are kept: main's imp-069 test stays in the phone block, followed by imp-091's four More tests; imp-093's tablet block (768 and 1023: count, zero, API down) is unchanged. The phone count test gains imp-093's check that only one "need attention" text is announced on the page (the hidden sidebar's and Open menu's copies aren't). The comment above it points at the tablet tests and names the shared pattern.
