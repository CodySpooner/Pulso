## What changed

The first load used to shift the page when the fixture data landed. Two things caused it. The Sources and Coverage skeletons were about half the loaded height. And the page header's "As of" line only appeared once data arrived, which pushed every panel down 20 px. Each first-load skeleton now takes the shape of its loaded panel. Only the pending branches changed: every loaded, empty, error and stale branch renders as before.

| File | Change |
|---|---|
| `apps/web/src/components/data-health/sources-table.tsx` | While pending, the panel renders the loaded table and phone list. The real table header and the static Planned rows are shown, plus one skeleton row per Phase 1 source (4). Each skeleton row is `row-h-comfortable` with the name cell's `py-1.5` and a 32 px name bar, so it is as tall as a loaded row. The per-column bars are about as wide as the loaded content, so the header doesn't slide sideways. Phone cards copy the loaded card: name and pill, the two-line facts block, then the toggle and Run now. Skeleton rows and cards are `aria-hidden`. The empty check now reads `sources.data && rows.length === 0`, and the order is error → empty → table (pending and error are exclusive states) |
| `coverage.tsx` | The pending branch uses the loaded layout: 4 rows on the same label and cells grid, the axis line, the **real legend** (static, shared with the loaded branch as `legend`), and an open-gaps block. That block has a heading bar, a `h-7` header row and two `row-h-compact` rows, so it also tracks 44 px touch rows |
| `summary-cards.tsx` | `CardSkeleton` shows 5 bars for the 5 facts, at the facts' `gap-2` row gap (it had 4 bars at `gap-3`) |
| `data-health.tsx` | The header meta shows "As of —" until the first fetch, the app's existing no-data pattern (Daily Pulse, the top bar). The line now exists from the first paint. | `e2e/data-health/loading-screenshots.spec.ts` (new) | Loading and loaded screenshots at the same size. It runs only in the `screenshots` project |

The 150 ms skeleton delay, the shimmer and the reduced-motion clamp are untouched (`ui/skeleton.tsx` didn't change). Every bar uses tokens and Tailwind scale steps only.

## Limitations

- **Four skeleton rows** fit Phase 1's four seeded collecting sources (a `ponytail:` comment marks this). Any other count adds or removes about 45 px per source at 1440 when the data lands.
- **At 375 the cards' facts wrap after load.** "Off here: live collectors run only on the collector host" wraps to 2 lines, the open-gaps fact also wraps, and the Backups strip label wraps. Host grows 36 px and Backups 14 px. The skeleton can't know the copy, so CLS is 0.025 there (budget 0.1).
- **The open-gaps block is sized for two ranges,** the fixture's count. Zero ranges ("No open gaps…") is shorter and up to 8 ranges is taller. This sits below the fold at both widths with the fixtures.
- **The CSV import panel's skeleton** (`import-panel.tsx`, owned elsewhere) is shorter than its loaded panel. It is the last panel, so nothing below it moves.
- **imp-081, if merged first,** adds an Import CSV action beside Run now. The actions-column bar (`w-22`) may then need to be wider to keep the header from sliding a few pixels. Row height is unaffected.
- **CLS was measured on `next dev` with fixtures,** not on a production build or real devices. The height ratios don't depend on the build.
