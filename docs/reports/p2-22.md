## The rule (DEC-258)

```sql
SELECT … FROM (
  SELECT shipping_options.*, sources.key,
         max(observed_for) OVER (PARTITION BY coalesce(variant_id, :single_live_variant_or_null)) AS day,
         rank() OVER (
           PARTITION BY coalesce(variant_id, :single_live_variant_or_null), origin_country
           ORDER BY observed_for DESC, captured_at DESC, raw_payload_id DESC
         ) AS capture
  FROM shipping_options JOIN raw_payloads … JOIN sources …
  WHERE listing_id = :listing AND destination_country = 'US' AND quantity = :q
) newest
WHERE capture = 1 AND observed_for = day [AND method = :method]
ORDER BY id DESC
```

- **Why one window level is enough.** Each origin's rank-1 capture is its newest day's newest capture, because `observed_for` sorts first. That capture is priced only if its day is the variant's newest day. If the per-origin rank sorted by `captured_at` first, a backdated CSV row imported later would become an origin's rank-1 capture. Its day is older, so it would knock out that origin's real newest-day capture. The fourth new mutation proves this.
- **Unchanged from DEC-250:**
  - the partition key (`coalesce` for a single-variant listing);
  - the filter on this listing, US and this quantity;
  - the method filter, applied after the ranking;
  - the later raw payload on a tie;
  - the newer parse on a re-parse (`id DESC` with `setdefault`);
  - the gap codes.
- **Fail closed (R-16).**
  - Without a method, an unpriced origin can't win cheapest. When the only other quote costs more, the margin comes out lower, never higher.
  - With a method that only an older day lists, the answer reads `freight_missing`.
  - If no variant's newest day lists the method, the answer is still `freight_missing`. If another variant's newest day lists it, the answer is `freight_variant_mismatch`, as before.
- **Why a day and not a run.** CJ's tracked plan asks CN and US for each variant together (`cj/tracked.py` `plan()`), and the weekly `cj.freight` slot runs at 04:30 UTC (`schedules.py`). Grouping by collector run would let a same-day retry of one origin hide the other origin's answer from earlier that day.
- **Why not fix 2** (rank over the freight `raw_payloads`, or a no-quote marker row): the loader would have to parse each source's request JSON, or the CJ writer would need a new kind of row. A CSV quote with no origin would still need a rule of its own. Fix 1 covers both paths with one SQL change.
