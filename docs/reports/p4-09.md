### API as built

- `GET /v1/products?format=csv&<the JSON page's filters and sort>` returns 200 `text/csv; charset=utf-8` with `Content-Disposition: attachment; filename="pulso_discover_<YYYY-MM-DD>.csv"` and `X-Total-Count`. Over 50,000 matching rows it returns 422 `application/problem+json`, code `export_too_large`, detail "N rows exceed the 50,000 export limit. Narrow your filters." Any `cursor` or `limit` is ignored.
- Columns: `id, product, category, price_min, price_max, currency, velocity_7d, velocity_grade, velocity_gap, momentum_g7, stores, suppliers, best_margin, best_margin_pct, first_seen_at, as_of, stale`. These follow the table's on-screen order (Product, Price, Velocity, Momentum, Stores, Suppliers, Best margin, First seen, Freshness) plus `id`. Freshness exports as `as_of` and `stale`.
- **Reuse in later parts:** `csv_response(session, "<table>", HEADER, ordered_select, lambda chunk: rows…)`.

**What the acceptance tests show:**
- **Three pages, every row once:** with the stream chunk patched to 2 rows, each sort's export equals the three JSON pages walked by cursor, in order. A filtered export equals its filtered walk.
- **Formula guard:** titles `=HYPERLINK(…)`, `+1 lamp`, `-2 lamp` and `@SUM(A1)` come back with a leading `'`. `Lamp` comes back unchanged.
- **Over the cap:** with the cap patched to 5 and 6 matching rows, the answer is 422 `application/problem+json` and no CSV. 4 filtered rows still export.
- **BOM and money:** the file starts `EF BB BF`. Steady exports 15.00 / 25.00 with `currency` `USD`.
- **Workspace isolation:** workspace A exports best margin 15.03 at 50.12 %, workspace B 17.70, and a workspace without settings blank cells.
- **Playwright:**
  - the button and `E` (table and grid) download `pulso_discover_<today>.csv`, and the request carries the filters and sort with no cursor;
  - with 0 rows the button is locked: focus shows "Nothing to export", and neither a press nor Enter sends anything;
  - "Preparing export…" takes no second press;
  - over the cap, the alert shows the API's message with no Retry and no download, and changing a filter clears it;
  - a refused connection gives "Couldn't export. The Pulso API didn't answer." Retry from the keyboard then downloads, and focus is back on Export CSV.

## Departures and notes for review

- **Formula guard on text cells only** (DEC-316 c). The brief says any cell. Numbers are exempt so a negative margin stays a number in Excel. A number formatted by the server can't hold a formula.
- **Export CSV sits on the count line**, which is the Discover layout's third toolbar row ("1,284 products · as of … [action]"), rather than the controls row. There it has room for "Preparing N rows…" and appears in both views.
- **`E` scope:** focus in the results (grid or table), as the brief and the feature note say. V stays page-wide. A visible `E` hint was left out because it would suggest E works from anywhere. The button carries `aria-keyshortcuts="E"`.
- **Phone label:** below 640 px the busy label is "Preparing…". The N is still announced, and shown from 640 px up.
- **`client.ts` media typing** (DEC-316 e) is a one-line change to a shared file. Without it, the documented `text/csv` breaks the typing of every `/v1/products` consumer. The only other `text/csv` response is the import-template download, which goes through `<a href>`, not the client.
- **Conflict in the Design note:** [[Tables & Data Density]] § CSV export names `GET /api/v1/{resource}/export.csv` and `pulso-{view}-{date}.csv`. The brief and [[CSV Export & Import]] use `?format=csv` and `pulso_<table>_<date>.csv`, and I built those (DEC-316). That note isn't mine to edit, so the fix is in the lead lines below.
