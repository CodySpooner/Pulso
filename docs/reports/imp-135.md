## Root cause

A query with no data goes back to `pending` while it refetches (TanStack `fetchState`: `data === undefined` → `status: "pending"`). So every panel's skeleton replaces its `PanelError`, the focused Retry included, and focus falls to `<body>`. The API-down page goes the same way: both core calls are pending under "Refreshing…", so the full page skeleton replaces the error. With `retry: 1` the error stays away through the 1 s retry delay, and then a new error with a new Retry mounts. Neither `PanelError` nor `StaleLine` had a live region.

**Defaults recorded in DEC-217** (all within the brief):
- **Settled** means every query has stopped fetching, not just the pressed one. The page's Retry refetches every admin query, so its outcome waits for all of them. A panel's outcome can wait a moment for an unrelated refetch.
- **Page-level success** focuses the Collector host heading, the first panel back, which has a visible ring. The `h1` has no ring (`outline-none`).
- **`StaleLine` is included.** Its Retry stays mounted through the refetch. A success unmounted it and dropped focus to `<body>` (the same bug), and its failure was silent.
- **The run drawer is left as is**, with no scope. Radix keeps focus in the dialog, which aud-014 judged acceptable.
- **The announcement** is the visible title (or the stale line's "what") plus the visible detail. No new copy.

## Tests

- **Vitest, `retry.test.ts`** (3 tests): an error still shown failed; an error shown since the press failed in its place; no new error means restored, even beside an error from another call. All were RED before `retry.ts` existed.
- **Playwright, `retry-focus.spec.ts`** (chromium, 8 tests). An init-script MutationObserver records what a screen reader hears: a live region whose text changes after insertion, or an alert inserted with text.
  - **Page-level, at 1440 and 375:**
    - success → the "Collector host" heading is focused with a non-`none` outline, and nothing is announced;
    - failure → "Refreshing…" shows and Retry is gone (it unmounted), then the new Retry is focused and exactly one announcement is heard (still one after 500 ms). No horizontal scroll at 375.
  - **Coverage:**
    - success → the "Coverage" heading is focused, the heatmap is back, and nothing is announced;
    - failure → the press plus TanStack's one retry (2 requests), then Retry is focused and one announcement is heard. A later background refetch (tab refocus, 2 more requests) with body focused announces nothing and leaves focus on body.
  - **Page-level background:** neither the first load nor a background refetch announces anything or takes focus.
  - **Stale line:** a failed Retry keeps focus and is announced once; the next Retry succeeds, the line goes and the "Coverage" heading is focused.
  - **RED on `168b413`:** the 4 page tests and both coverage tests (focus never left `<body>`), and the stale-line test (0 announcements). The two silence tests pass on the old code by design: they guard the new focus/alert logic.
  - **Mutation check:** when `useRetry` starts in the failed state, both silence tests fail (focus taken and an alert on first load). The fix was then restored.
