## Change

At 768–1023px the top bar has two icon-only buttons, **Open menu** and **Open command palette**. They had an `aria-label` but no tooltip, which Design/Accessibility asks for ("Icon-only buttons: `aria-label` always, plus a tooltip"). `apps/web/src/components/shell/topbar.tsx` now wraps each one in the shared `Tooltip`, the same way `ThemeToggle` does:

- **Open menu:** the tooltip reads "Open menu" and sits at `align="start"`. Centred, Radix pushed it flush against the screen's left edge (x = 0); now it lines up with the button and keeps the 16px page gutter.
- **Open command palette:** the tooltip reads "Open command palette" followed by the `ModKey` cap ("Ctrl K", or "⌘ K" on a Mac), the same cap the desktop search trigger shows.
- **No sticky tooltip on touch (`keyboardFocusOnly`, 3 lines):** Radix opens a tooltip whenever its trigger takes focus, unless a pointer press caused that focus. The menu sheet and the palette hand focus back to their button when they close. After a tap or click, that focus would open the tooltip and leave it over the page until something else took focus. The trigger's `onFocus` now skips Radix's open when the button isn't `:focus-visible`, so the tooltip follows the same rule as the focus ring.
  - Keyboard focus, including focus returned after Esc, still opens it.
  - Hover is unaffected.
  - A tap never opened it: Radix ignores touch pointer moves, and a tap's own focus comes from a pointer press.

The following stay unchanged:

- **Accessible names:** "Open menu" and "Open command palette" (`aria-label`).
- **Focus return:** `app-shell.tsx`, `mobile-nav.tsx` and `command-palette.tsx` aren't touched.
- **Shortcuts:** Ctrl+K / ⌘K and `[`.
- **Hit area:** each button is still a `Button` with its built-in `hit-area` (44×44 under a coarse pointer).
- **Phone and desktop:** both buttons stay `hidden md:inline-flex lg:hidden`, so below 768px and from 1024px nothing renders differently.

No API, schema, dependency, network destination, source, secret, env, CI or protected-path changes, and no new component. **DEC-187 is unused**: the `:focus-visible` gate is local to the two triggers and is described in the code comment and here. No other tooltip trigger gets focus back from a dialog. RunButton, the workspace chip and the "Data as of" link open none.

```tsx
  <TooltipContent align="start">Open menu</TooltipContent>

```

## Deferred findings (not fixed here)

- **Description repeats the name (P3, observation).** While a tooltip is open, Radix points the trigger's `aria-describedby` at a hidden copy of the tooltip text. When the text equals the `aria-label`, as on Open menu and on the existing ThemeToggle, a screen reader may hear the name twice on keyboard focus. Check with NVDA or Narrator in the Phase 2 spot check (Design/Accessibility, Testing). If it repeats, give such tooltips `aria-label=""` on `TooltipContent`, or drop the duplicate there.
- **Shared gate later (P3, only if needed).** `keyboardFocusOnly` lives in the top bar because only these two triggers get focus back from a dialog. If another dialog ever returns focus to a tooltip trigger, move the rule into `ui/tooltip.tsx`'s `TooltipTrigger` instead of copying it.
