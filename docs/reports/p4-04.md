## Ceilings and limitations

- **Keyword history:** a re-decision rewrites the `product_keywords` row (DEC-281), so a keyword confirmed and later rejected disappears from earlier days. That makes it missing, never leaked; it can't make a past feature read the future.
- **Merges:** a merged-away product's confirmed keywords aren't inherited by the survivor; only the survivor's own confirmations count.
- **Late gap detection:** a gap the audit records after day t's cutoff appears from day t+1's row on. Day t's own demand row already shows `has_gap` from target coverage.
- **Fills:** a fill never clears a `missed_runs` date (DEC-060 D4). Data Health's Open gaps list drops a filled gap, while its heatmap shows `filled`. The test compares against the view's `gap` days, which the fixture never fills.
- **Seller coverage** is a global ratio (panel stores over tracked stores), not per product.
- **Relisting:** a live crawl that relisted a listing reset its `delisted_at` (DEC-247 h), so that history isn't rebuilt. The crawler stays off (DEC-261).
- **`trends()`** reads every point of every capture before the cutoff (marked `ponytail:`). Bound it if a 5-year backfill makes the nightly job slow.
