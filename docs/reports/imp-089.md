# imp-089 — Import panel: a running import keeps its Source select

Branch `CodySpooner/imp-089-import-source-guard`, on `origin/main` `08b1d6d` (no rebase needed). This is a web-only change: no API, dependency, env file, source, collector or protected path is touched. Recorded as DEC-179, proposed (imp-089).

## The bug (imp-081 report, P2)
The Source select's `onChange` called `commit.reset()` and re-checked the open file for the new source. TanStack Query's `reset()` detaches the panel from the running mutation. The server still imported the file, but the panel never showed the outcome, never offered Open runs and never refreshed the source data. Instead it showed a fresh check of the same file against the other template.

**Reproduced** with the fixture commit route held pending (`page.route` awaiting a promise). Pressing ArrowUp on the select during the import, then a change event, switched it to `cj`: the test fails on `main` with `Expected: "fx_frankfurter"`, `Received: "cj"`.

## The fix
`apps/web/src/components/data-health/import-panel.tsx`, select element only (+6 / −2 lines):
- `aria-disabled={commit.isPending}`. The select stays focusable, and screen readers announce it as unavailable. The reason is already spoken by the polite status ("Importing rates.csv…").
- `onChange` returns early while the commit is pending. React's controlled select then puts the value back, so keyboard arrows, typeahead and a value set by assistive tech all leave the source unchanged.
- `aria-disabled:pointer-events-none`, so a click or tap can't open the native list.
- While locked, the text and chevron use `--subtle-foreground` (the chevron via `peer-aria-disabled:`).

Ordinary switching is unchanged. Once the import ends (success, failed run or error), the select works as before: a change re-checks the open file and clears the outcome.

**Why not native `disabled`:** it drops the select from the tab order and blurs it. The existing DEC-145 test "an import that finishes after focus moved elsewhere leaves focus there" focuses this select mid-import, and it still passes unmodified.

- **States:** no new view. The import panel's existing skeleton, empty, error, stale and "no import adapter yet" states are untouched.
- **Keyboard and focus:** the select stays in the tab order with a visible ring while locked, and focus is never moved. **Reduced motion:** nothing animates.
