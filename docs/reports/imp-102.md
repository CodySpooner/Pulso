## Deviation: the retry waits are `[2]`, not `[2, 2]`

The brief and the audit expected `[2, 2]` (4.00 s). On current `main` the test makes one real 2 s wait, and its baseline is 2.07 s / 2.06 s, not 4 s. The audit measured `aa48a0f`. Since then, P1-49 (`89b0fd0`, "stop a Trends run after two failed attempts") changed this same test from `http_requests == 4` to `== 2`. With `collector_max_retries = 1` the run now makes one request and one retry, and the framework backs off once at `collector_backoff_base_seconds * 4**0 = 2` (`framework/lifecycle.py`). Asserting `[2, 2]` fails (`assert [2] == [2, 2]`). The test therefore asserts the real `[2]`, with a comment naming P1-49. It still proves zero real sleeps and the base-2 backoff. Because of this, the Trends test saves about 2 s, not 4 s.
