### Formula (DEC-246 b)

```
goods    = convert(q × C)                   # one half-even FX rounding, never q × round(C × fx)
freight  = convert(F(q))                    # its own rate, for its own UTC date
duty     = 0 if ddp else d × goods          # d unresolved → null + duty_not_set
customs  = 0 if ddp else customs_fee        # per order
landed   = goods + freight + duty + customs
payment  = pf_bps × P + pf_fixed
shopify  = shopify_bps × P
returns  = returns_bps × P
margin   = P − landed − payment − shopify − returns     # before ads = break-even CPA
margin_bps = margin / P
```

### Rounding rule (DEC-246 a)

Each money line is computed exactly and rounded **half-even once** to USD cents:
- FX lines go through `convert_minor(..., rounding=ROUND_HALF_EVEN, inverse=True)` (DEC-088), on `q × C` in the supplier's minor units.
- Basis-point lines use `round(Fraction(minor × bps, 10000))`: exact integer rationals, and Python's `round` on a `Fraction` is half-even.
- Duty is taken on the rounded goods line.
- `landed_cost_minor` and `margin_minor` are integer sums of the rounded lines, so the breakdown always adds up. `margin_bps` is half-even too.
- Exponents come from `pulso_core.money` (JPY 0, USD 2, KWD 3).

### Missing codes and sources

- **Codes, in this order:** `price_missing`, `supplier_cost_missing`, `freight_missing`, `freight_variant_mismatch`, `duty_not_set`, `fx_missing`.
- **`sources`** is keyed by input name: `price_minor`, `unit_cost`, `fx_unit_cost`, `freight`, `fx_freight`, and each fee, returns, duty and customs input. Each entry has `source`, `as_of` and `raw_payload_id`.
  - Observations carry their `sources.key`, `captured_at` and capture id.
  - Settings carry `settings`; request overrides carry `owner_estimate`. Both have `as_of: null`, because settings has no timestamp column.

### Choices made under the non-stop rule (all in DEC-246)

- **FX date.** FX uses the rate's own date, within 4 days up to the observation's UTC date (the Profit note's look-back). Its `captured_at` doesn't count: the daily job usually stores day d's rate on d + 1, so a capture-time cutoff would make every rate a day late.
- **FX source.** On a date tie, the daily blend beats a `manual` CSV rate.
- **Freight method.** Without a `method`, the cheapest exact quote in USD is used, taken from the latest quote per origin and method.
- **Supplier.** Without `supplier_listing_id`, the best complete margin wins. If no row is complete, the row with the fewest missing inputs wins, then the lowest id.
- **Reference price.** It is the lower median of live USD store prices, which is one listing's price, with its trace. It applies at quantity 1 only; a q-unit order needs `price_minor`.
- **DDP** zeroes duty and the customs fee, as the Profit note's acceptance says.
- **Duty bound.** The duty override accepts 0..100000 bps, not 0..10000, because DEC-237 (h) says US duty can pass 100% (the Profit slider goes to 150%). Fees and returns stay at 0..10000.
- **Duty resolution** is the override, then `settings.duty_default_bps`, then not set. Product and category rules have no table yet, and no migration was added.
- **Merged products.** A merged product id gets 404, not 308: the Profit tab sits on the survivor's URL.
