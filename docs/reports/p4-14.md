## Behaviour

`trend_scores(rows, week_ago, categories, primary, saturation)`:
- `rows` are day t's `product_daily_features` rows, every family. `week_ago` are day t−7's, read only for G7(t−7). Nothing else is read, so the point-in-time rule is the rows' own (DEC-031).
- `categories` maps every product to score to its lineage, as in Saturation. Only those products are scored or normalised over.
- `primary` names each product's primary demand family. Demand Signals rule 1 makes that a per-product choice, and Lifecycle (DEC-307) already takes the primary family's rows from its caller, so SC-6 picks it once for both (DEC-323 a).
- `saturation` holds each product's Saturation value from `saturation_scores()`.

| Component | Raw | Weight | Source | When missing |
|---|---|---|---|---|
| `<family>_g7` | the primary family's stored G7 | 0.40 | `shopify_stores` or `cj` | Required: no value, with a reason |
| `<family>_acc` | G7(t) − G7(t−7) from the two days' rows | 0.20 | same | Renormalised; "insufficient signal" |
| `gt_slope` | the `gt_interest` row's stored `gt_slope` (R-18) | 0.25 | `google_trends` | Renormalised; "insufficient signal" |
| `ads_growth` | — | 0.15 | none | Always; "no source yet" |
| saturation penalty | Saturation 0–100 | 15 points at 100 | `shopify_stores` | Takes nothing off; named in `missing` |

- **Value:** T = Σ w_eff × z from `pulso_core.scores.explain()`. pre = 50 + 50 × T / 3, penalty = 15 × max(0, (S − 50) / 50), Trend = clamp(pre − penalty, 0, 100).
- **Robust z:** the shared `robust_z` (DEC-318 a): within the category, up the lineage when n < 30 or MAD = 0, then global; ±3. Each component has its own cohort, so families never mix. A present input with no z is missing with its source set and keeps its raw value.
- **Log growth and the stable panel:** G7 is already ln((V7 + 5) / (V7 prev + 5)) over the listings covered at t−14 and t (DEC-275 d), so 3 → 30 units reads 1.48 and newly tracked listings never read as growth. Ads' stable advertiser panel waits for an ads source.
- **No value, with its reason, never 0:** `no demand family`, `no velocity growth`, `velocity growth doesn't vary`. `value` and `explanation` are then None.
- **Shopify off (DEC-261):** a `cj_stock` product scores from CJ and Trends, with `missing: ["ads_growth", "saturation"]` and no penalty.
- **Acceleration without `family_velocity()`:** the vault Log line from p4-03 says `<fam>_acc` comes from `family_velocity()`. Its value is the same subtraction (DEC-310 a), but its `has_gap` and reasons need `days_observed`, which Trend doesn't use. The gap flag here is either row's `has_gap`.

### The vault worked example
The example is consistent with the formula to 0.1 points: with unrounded z (1.956, 1.205, 1.128), T = 1.5357, pre = 75.60, penalty = 6.99, **Trend = 68.61**, points +15.3, +4.7, +5.5. The table's rounded z give T = 1.532 (the note says 1.535), and Trend is 68.6 either way. Two body fixes:
- `explanation.missing = ["ads"]` → `["ads_growth"]`: `missing` holds component names, and the component is `ads_growth` (its Inputs key). Score Definitions §5 had the same `["ads"]`, now fixed too.
- A line saying T uses the unrounded z.
