# imp-423 — `W`, the ★ key (Phase 4 WF-2f)

Task `task_aac8fc3dc23d` / `ctx_d178db494918`, branch `CodySpooner/imp-423-w-shortcut-star`, DEC-364 (proposed). Web only: no migration, no API change, no new dependency.

## What was built

- **`W` toggles the ★ on the focused product, on any page.** One window listener (`WatchKey`) is mounted in `app/(app)/layout.tsx`. `starFor()` picks the ★ inside the closest `[data-product]` of the focused element (a Discover card or table row today). With nothing of a product focused, it picks the page's own Watch (`data-star="page"`, the Product Page header), so `W` works there from anywhere, as `B` does.
- **Guards:** never while typing (input, textarea, select, contenteditable), with Ctrl, ⌘ or Alt, on a held key, or inside a dialog or menu (the Product Page's lists menu has letter typeahead). A product with no ★ does nothing, even on a page that has one.
- **Same path as the ★:** `W` clicks the ★ button, so it runs the same `useStar` mutation: `PUT`/`DELETE /v1/products/{id}/watch`, the optimistic flip of every cached read (`applyWatch`), the rollback on an error, and `refreshWatchlists` invalidation.
- **Announcement:** once the answer is back, a polite live region says "Added {title} to Main", "Removed {title} from Main" or "Couldn't add {title} to Main. Try again." It does this for clicks as well as `W`; before this, a failed ★ flipped back silently. The region is `aria-live="polite"` and not `role="status"`, so each page's toast stays its only status.
- **Listing:** no shortcuts help or palette lists `B`. `B` is only named on its button (`aria-keyshortcuts="B"`, title "… · B"), so `W` is named the same way on every ★ and on the Product Page's Watch (`aria-keyshortcuts="W"`, title "Add to Main · W").

## Left out, and why

The ★ isn't on **Screener rows** or **board cards and table rows**. `ScreenerRow` and `BoardItem` carry no `watched` / `watchlist_ids`, and the API has no batched watch-state read; the closest reads are per product, or per list and paginated. The task's rule (no API change) leaves both out and adds a backlog row for each, below. `W` on those rows does nothing: they have no ★ to toggle and never fall back to a page ★. Once their reads carry the two fields, rendering `StarButton` inside a `data-product` element gives them `W` with no key code. Screener table rows already carry `data-product` (the shared `ProductTable`). Daily Pulse rows: not touched (p4-36); they carry no `data-product` today.

This drops acceptance (2), "Screener rows and board cards show the star", and the Playwright cases for a Screener row and a board card. Those cases run on a Discover table row and the Product Page instead.
