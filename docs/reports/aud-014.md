## Result

**8 findings: 3 P2 and 5 P3.** Every one is new to [[Improvement Backlog]], `docs/BACKLOG.md` and the unmerged aud-010/011/012 reports. 13 more observations are already owned and are listed under Duplicates.

Recovery is short everywhere it is visible. Every failure walked recovers with **1 click or tap** on Retry once the API answers. Every Retry and Copy control passes the 44 px touch probe (0 of 9 short). The import panel moves keyboard focus correctly after each step. The problems are about what the page *shows* while something is failing:

- **A failed refresh deletes what was on screen.** The page goes from 4 sources and 4 coverage rows to 0 and keeps saying "As of 14:00".
- **One failed call paints a problem green.** When only the host call fails, an Overdue source reads Healthy, and the attention count drops from 2 to 1.
- **Offline actions queue silently.** A source disable the owner cancelled while offline is sent when the connection returns, and the source turns off.

## Method

- **Fixtures only.** `mockAdminApi` (`apps/web/e2e/data-health/fixtures.ts`) answers every `/api/v1/admin/*` call, with the clock pinned to 2026-10-22 14:00 UTC (Shopify Blocked, CJ Healthy, Google Trends Overdue, Frankfurter FX disabled with CSV import `ready`). Each failure is a Playwright route layered on top: `abort("connectionrefused")` for "API down", or a `503`/`500`/`422` RFC 9457 problem body for "API answered with an error". Offline is `context.setOffline(true)`. The 422 text is the real parser's message on this SHA (`parse_csv("fx_frankfurter", …)` run locally).
- **Environment.** `next dev` with the E2E auth bypass, reduced motion, Chromium at 1440×900 and 375×812, dark and light. Touch checks use a `hasTouch` context with imp-026's 44 px `elementFromPoint` probe. No live source, collector stack, Clerk session, secret or env file was involved.
- **Walk script.** A scratch Playwright spec and config (44 tests) kept outside the commit, as in aud-010 and aud-011. Only the dev-server port moved, to 3914. Every test writes JSONL: on-screen text, geometry, focused element, request counts.
- **Counting rules.** A click is one pointer press on an app control; a file pick in the OS dialog counts separately. Keys are listed as pressed. "Tabs from load" starts with focus on `<body>`.
