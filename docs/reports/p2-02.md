**Header stats.** The stats come from each live listing's latest snapshot (`DISTINCT ON listing_id`, `delisted_at IS NULL`):
- store count and supplier count, each traced to the newest snapshot in its set;
- the lowest and highest USD retail price, each traced to the snapshot that sets the bound.

Each stat names its source family, its UTC `as_of` and its `raw_payload_id`. `stale` is true when `as_of` is more than 2× the source's `expected_interval` old. A stat with nothing behind it is `{value: null, reason}`, never 0 (DEC-040).

**Merged and unknown ids.** A merged id answers 308 with a relative `Location: {survivor}?{query}`, and the page then shows the survivor's URL. An unknown id is a 404 problem, and a malformed id is a 422. The page shows both as "No product has this ID" and doesn't retry them.

**Tabs.** Overview, Trends, Suppliers, Sellers and Profit follow the WAI-ARIA pattern with manual activation, and each has a flag (`TAB_FLAGS`). `?tab=` deep-links to its tab. An unknown or flagged-off value shows Overview, with no error. A tab switch replaces the URL, so it adds no history entry. Each tab body names the task that builds it (UX-4…UX-8) and shows no number.

**`<Metric>` card.** It opens on hover, keyboard focus and tap. It shows the source, the UTC as-of and its age, the method (estimates only), "Stale" in words with an icon, and the raw payload id as selectable text. No admin raw-payload view exists yet, so there is no link (backlog row 1).

**States.** Loading skeleton, not found, error with Retry and Error ID, stale (banner plus a warning caption per stat), and no source yet. Refetch failures with data on screen use Data Health's stale line.
