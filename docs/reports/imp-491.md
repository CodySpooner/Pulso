# imp-491 + imp-575: Discover never sits invisible, and its table fits 1440 px

Task `task_17ce70b3bda0` / `ctx_01441dd9f6e8`, branch `CodySpooner/imp-491-discover-fade-fit`, DEC-366 (proposed). Web only: no migration, no API change, no new dependency.

## What was built

- **No Motion-held fade on first paint (imp-491).** Discover's keyed view wrapper was an `m.div` with `initial={{ opacity: 0 }}`. Under `LazyMotion` its features chunk loads after first paint, so the table or cards sat at opacity 0 until that chunk arrived. A test that holds the chunk back shows they never become visible. The wrapper is now a plain `div key={view}` with the CSS fade `/watchlists` uses (`animate-in fade-in-0 duration-(--duration-fast)`). A view switch remounts it, so the fade still plays (120 ms, the `fast` token). The global `prefers-reduced-motion` rule cuts it to 0.01 ms. The product page's tab panel had the same `m.div` around every tab, which hid Overview on a full page load, and it gets the same CSS fade. Radix mounts only the active panel, so each tab switch still fades.
- **The table fits 1440 px (imp-575).** At 1440 px the ten columns needed 1255 px in a 1140 px card, so Freshness scrolled inside the table. Three changes, recorded as DEC-366:
  - cells have 8 px of padding-x, so 16 px between columns (the Compact padding in Design/Tables & Data Density), with 12 px kept at the table's left and right edges. This saves 72 px;
  - below 1536 px the product column is at most 240 px and drops its category caption, so the name keeps about the room it had beside the caption at 320 px. The category still shows on the card and the product page. From 1536 px nothing changes;
  - in the table, Freshness says "· blocked" or "· paused" where the card says "source blocked", with the full phrase on hover. Without this, the degraded state (a source blocked) still overflowed by 39 px.
- **Measured** (`scrollWidth` / `clientWidth` of the table region, fixture rows): 1440 px 1140/1140, also with a source blocked; 1536 px 1236/1236 both ways; 1920 px 1620/1620 both ways. Before: 1255/1140 at 1440 px.
- No column is hidden. The Screener shares `ProductTable`, so it gets the same padding and product column. Its 9 default columns scroll less as a result.

## Tests

`e2e/imp-491/fade-fit.spec.ts`:

1. **Discover, Motion's features never loaded.** The spec fetches each `motion-features` chunk and never answers the one that contains `domMax`. Its async loader shares the name and is on the boot path, so it still loads. Then it checks that the table is at full opacity within 1 s of loading, times every ancestor's opacity, and the same after a click to Grid and `V` back to Table. It also checks that the switch ran the CSS `enter` animation.
2. **Reduced motion.** With `prefers-reduced-motion: reduce`, a switch's wrapper still carries `enter`, cut to under 1 ms.
3. **The product page's tab panel, features never loaded:** Overview and then Trends are at full opacity.
4. **1440 px fit:** all ten headers are present and the table's `scrollWidth` ≤ `clientWidth` with 60 fixture rows.
5. **1440 px fit with a source blocked:** the same check, with the rows saying "· blocked".

Before the fix, tests 1, 2, 3 and 4 failed: opacity 0, `animation-name: none`, opacity 0, and 1255 > 1140.
