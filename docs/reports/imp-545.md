## Outcome

A CJ tracked run now writes a stock-only listing row. The readers in part a read it per field:

- Price reads skip stock captures.
- Stock reads take the newest row with stock fields or from a stock capture.

On fixture databases, a stock-out now fires R-23 once. Previously, CJ stock-outs seen by alerts were 0. The listing keeps its unit cost when its newest row is a stock row, and a later price row no longer hides a current stock-out. `unit_cost(listing, variant)` returns the detail price after a tracked run; on main it returned None.

## Decisions (DEC-348)

- **An unknown total supersedes an older level** (DEC-120: "an owned null supersedes that writer's older values"). The same `STOCK_READ` serves `stocked()`, `alerts.latest()` and the view. So 0 followed by unknown reads "not known out of stock" (DEC-243), and R-23 re-arms.
- **The price filter skips only stock captures, for listings and variants alike.** It is not narrowed to the detail writer. A CSV-only `csv-sku:` variant has no detail row, so narrowing would drop its cost, and the money path must not change for listings without stock rows.
- **One predicate in `pulso_core`.** `pulso_sources` imports it. The frozen migration repeats it as SQL text. `pulso_ml`'s `FAMILIES["cj_stock"]` keeps its own copy, as before.
- **Pulse follows the view with no edit (DEC-349).** `dated_economics()` reads the head view revision's text, so with 0024 as the head it reads 0024. Its `listing_snapshots snap` count stays 3: the edits add only a `raw_payloads` join on a snapshot that is already cut off. imp-550's `test_the_dated_view_is_the_live_view_text_but_for_the_cutoff_rewrites` holds the dated text to the live 0024 view, and passes.

## Part b (the next task, same design)

These readers still take one latest row. Until part b merges, a CJ listing whose newest row is a stock row shows no unit cost and a masked stock on them. No CJ tracked run is scheduled or live, so no such row exists yet.

1. **Suppliers tab lateral** (`routers/product_suppliers.py`): a price lateral with `PRICE_CAPTURE` and a stock lateral with `STOCK_READ`. The `stock` Stat gets its own `captured_at` and `raw_payload_id`. Update the `as_of` field's description, which says it covers stock, and regenerate OpenAPI and the client.
2. **Discover `latest_snapshots`** (`routers/products.py`): the price row filtered by `PRICE_CAPTURE`, with `available`/`stock` from a `STOCK_READ` lateral. Two Listing-driven laterals, ordered by `Listing.id` to keep `min()` tie-breaks, avoid a lateral per snapshot row. The Overview's in-stock offer filter follows.
3. **Matcher price fact** (`pulso_ml/matching/matcher.py` `load_facts`): `PRICE_CAPTURE` in the `latest` lateral (join `RawPayload`).
4. **Match review `listing_detail`** (`routers/matching.py`): `PRICE_CAPTURE`.
5. **Pulse `suppliers()`** (`routers/pulse.py`): its stock reads take `STOCK_READ`, so an unknown total supersedes there too. This task's ownership allowed only `dated_economics()` in that file.
6. **Acceptance:** (b) and (c) through `GET /v1/products/{id}/suppliers` and the overview, plus a matcher fact test.
