# imp-168 — The run drawer's Retry is announced when it fails

## Root cause

DEC-217 (d) gave the run drawer no retry scope, because Radix keeps focus inside the dialog. `useRetry` outside a scope never learns a press failed, so the drawer's `PanelError` alerts stayed empty. The second half: Radix's FocusScope moves the focus of a removed control to the dialog container, not to `<body>`. So even inside a scope, DEC-217's "lost focus" test (`document.activeElement === document.body`) would never hold in the drawer. Neither the new Retry nor the title could take focus, and focus stayed on the container.

## Tests

- **Playwright, `retry-focus.spec.ts`, 4 new tests** (runs and targets × 1440 and 375). Each one:
  - checks that the first load's failure isn't announced;
  - makes two failed presses, each with exactly one announcement (polled, then rechecked after 500 ms) and Retry focused, the second with 0 Tabs;
  - runs a background refetch with the dialog focused: 2 requests, no announcement, the dialog keeps focus;
  - makes a restoring press: the title is focused with a visible ring, the runs list or targets table is back, nothing is announced, and there is no horizontal scroll.
- **RED on `0c9fd23`:** all 4 failed at "Retry focused" after the first press. The probe showed 0 alerts and the container focused.
- **Mutation check:** with the dialog clause removed from `takeLostFocus` (the scope kept), all 4 tests fail again at "Retry focused" after the first press. The fix was then restored.

## DECISIONS

DEC-225 is used (`proposed (imp-168)`). It narrows DEC-217 (c) and (d): the drawer is a scope, with the title as its target, and a focused dialog that contains the target counts as lost focus. It relaxes nothing in AGENTS.md §3/§4 or any compliance DEC.
