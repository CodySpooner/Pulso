# imp-273 — Products emptied by an undo leave Discover, search and the product page (DEC-271)

Improvement Backlog imp-273, targeting DEC-263's "Not here" line (p2-25, merged `8855082`). Branch `CodySpooner/imp-273-empty-products`, Orca task `task_6d98a7a63dd7`, dispatch `ctx_dfed11622df9`. ## The bug

Undoing an accept that formed a new product unlinks both listings, and undoing a split onto a new product merges its listings back. Either way the new product kept `status = 'active'` with zero listings. Discover filtered only `merged_into_id IS NULL`, and search matched product titles with no filter, so the empty product was listed in both, and its page rendered as a product with "no source yet" everywhere.

## Paths that can empty or refill a product

| Path | Empties? | Handled by |
|---|---|---|
| undo of an accept that formed a product (two product-less listings) | yes | `undo` → `settle` |
| undo of an accept that joined a product-less listing to a product | no, the partner stays | `undo` → `settle` (stays `active`) |
| undo of a split onto a new product, or `into` a product that was empty | yes | `undo` → `settle` |
| undo of a merge, or of an accept that merged | the target keeps its own listings; empty only if it was empty before | `undo` → `settle`; the source is un-merged to `active` |
| split, unlink | no: one listing at least stays (DEC-257 a, DEC-263 c) | n/a |
| merge | its source becomes `merged` (already) | n/a |
| matcher (score and GTIN passes), accept | no: they only move product-less listings, or merge through `merge` | n/a |
| merge or split `into` an emptied product (API only; the queue never shows one) | refills it | `merge` / `split` → `settle` |

## The change

| Where | Change |
|---|---|
| `packages/ml/src/pulso_ml/matching/decisions.py` | New `settle(session, product_ids)`: one `UPDATE products SET status = CASE WHEN EXISTS(listing) THEN 'active' ELSE 'empty' END` over the given non-merged products, after a flush. Called at the end of `undo` (every `from` and `to` product of its rows; it replaces the bare `session.flush()` there), `merge` and `split` (their target). |
| `apps/api/src/pulso_api/routers/products.py` | Discover and `list_categories` add `Product.status != "empty"`. `get_product` follows `merged_into_id` first, as before, then answers an empty product with 404 `no_listings`. |
| `apps/api/src/pulso_api/routers/search.py` | The product-title candidates add `Product.status != "empty"`. Merged products (`status = 'merged'`) still stand for their survivor. |
| `apps/web/src/app/(app)/products/[id]/product-page.tsx` | On a 404 with code `no_listings`: h1 "Product has no listings", and the not-found card reads "No listings left on this product" with a `PackageX` icon: "An undo in the Matching Queue moved its last listing off it, so Discover and search no longer show it. Its notes, scores and forecasts are kept." Same `EmptyState`, same Daily Pulse action. Without this the page said "No product has this ID … links Pulso gave you keep working", which is untrue here. |
| `apps/web/e2e/products/fixtures.ts` | `ProductMock.code` sets the problem's `code` (default stays `unavailable`). |

`match_decisions` gets only the undo's own rows, as before. No product, note, tag, score, forecast or feature row is deleted or moved.

### Why the service marks it, not the readers (DEC-271 alternatives)

I first wrote the reader-only version (`EXISTS` on `listings.product_id` in Discover, search and the page). It made the new test pass but failed **8 existing tests**: `test_products.py` (6) and `test_search.py` (2) seed products with no listings, such as "Unmatched", as ordinary products with no source yet. The brief requires those to stay green, so I reverted it and took the service option. Its ceiling: products emptied before this change stay `active` (see Leftovers).

## Tests

Postgres, each **failed first**:
- `apps/api/tests/test_matching.py::test_a_product_emptied_by_an_undo_leaves_discover_search_and_its_page`. Through the API: accept a pair of product-less listings (a new product), then split a listing off a two-listing product (a new product). Before each undo, the product is in Discover, in search for "Sunset lamp", and in `/v1/categories` (a category set as the taxonomy job would), and `GET /v1/products/{id}` answers 200. After both undos, Discover and search list only the kept product, the category list is empty, and both pages answer 404 `no_listings`. First failure: both emptied products still listed.
- `packages/ml/tests/test_matcher.py::test_a_product_an_undo_empties_is_empty_until_listings_join_it_again`. Service level: undo of accept → `empty`. Undo of split → `empty`, and the source stays `active`. Split `into` it → `active`, undo → `empty`. Merge the source into it → target `active`, source `merged`. Undo the merge → `empty` and `active`, and both listings are back on the source. First failure: `'active' == 'empty'`.

Playwright `apps/web/e2e/products/product-page.spec.ts` › "a product an undo emptied says its last listing moved off": 404 `no_listings` shows both headings and the Daily Pulse link. With the page's code check mutated, it fails.
