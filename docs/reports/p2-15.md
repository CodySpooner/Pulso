**The page.** One form with one Save, in five cards: a title and one line on the left, fields on the right (stacked on phones).

- **Market:** United States / US dollar as read-only text with a lock and "locked" for screen readers. Not disabled inputs, so it never reads as broken.
- **Fees:** processing rate % and fixed fee per order $ side by side, Shopify transaction fee %, ad cost per order (CPA) $.
- **Targets:** target margin %.
- **Duty default:** a segmented "Not set / Set a rate" choice. Not set shows "Duty not set. Landed margins that need it stay incomplete and read 'duty not set' until you set a rate, or the supplier's quote is DDP (duties paid)." Set a rate opens an empty box (never a pre-filled 0) whose hint says 0% is a rate. Then the import fee per order $.
- **Returns:** return rate %.

The owner types percent and dollars; `model.ts` parses the text digit by digit into basis points and cents (no floats; every bps 0..10000 round-trips exactly).

**Saving.**

- Save and Reset sit on a bar pinned to the bottom of the view, above the phone tab bar. Both are `aria-disabled` while the form is clean, so focus stays on Save after a save. Ctrl/⌘+S saves from anywhere on the page, inside a field too, and never opens the browser's Save dialog.
- Errors appear on blur, never while typing. A blocked save focuses the first invalid field and announces "Fix 2 fields to save: Fixed fee per order, Return rate."
- A failed save keeps every typed value and shows the cause and the error ID with Copy. An API 422 lands on the field its `loc` names.
- "2.90" against a saved 2.9 is not a change. An edit typed while a save is in flight is kept.
- A background refetch replaces the form only while it holds no unsaved change. Closing or reloading the tab with unsaved changes asks first.
- After a save: "Saved. The next margin uses these · as of Oct 22, 14:00 UTC". At rest: "Your workspace's settings · as of …".

**States** (every one is in the screenshots):

- **loading:** the form skeleton at its final layout, plus a screen-reader "Loading your settings…";
- **error:** the panel error with Retry and the error ID;
- **stale:** a failed refresh keeps the form and the owner's unsaved edit, under the stale line with the as-of time;
- **no source yet / first run:** "2 assumptions to check" (duty not set; processing 0%), each with a one-click link to its field, plus the duty "Not set" state;
- **saved** and **save failed** in the bar.

## Acceptance checks

### (a) A fee change moves the next profit calc

`test_a_fee_change_moves_the_next_profit_calc` (Postgres): a product at $29.99 with a $6.20 CJ cost and $4.85 freight.

- With processing at 290 bps + 30¢, 5% returns and 20% duty, the margin is 1503 cents (payment fee 117).
- PATCH processing to 590 bps, and the very next `POST /v1/profit/calc` gives 1413 (payment fee 207), with the input's source `settings`.
- Duty `null` then withholds the margin (`missing: ["duty_not_set"]`), and duty `0` completes it at 1627.

### (b) Isolation and constraints

- `test_workspace_a_patch_never_changes_workspace_b`: with real signed tokens, A's PATCH leaves B at the defaults, and B's PATCH with a forged `X-Workspace-ID: <A>` changes only B.
- `test_patch_rejects_what_the_table_rejects` (25 cases): every field at −1; every 0..10000 rate at 10001; duty at 100001; every money field at 2^63; a float, a string and a boolean; null for a non-duty field; country `CA`; currency `EUR`; null country; `workspace_id`; an unknown field. Each gives the 422 `validation_error` problem with `errors`.
- `test_settings_require_a_session`: GET and PATCH are 401 without a token.
- `test_first_get_creates_the_row_with_the_table_defaults`: a workspace without a row gets US / USD, every rate 0 and duty null; two GETs leave one row.
- `test_patch_round_trips_and_keeps_duty_not_set_apart_from_zero`: duty 0, null, 15000 and 100000 each round-trip through the response, a GET and the table. A PATCH without duty keeps it; echoing US / USD is accepted.
- The existing `test_two_workspace_settings_isolation` and `test_settings_boundary_rejects_invalid_values` pass unchanged.
