## Result

Both imp-134 leftovers are fixed.

1. **imp-153.** A CSV check or import that fails while the browser is offline now reads "You're offline. Retry once you reconnect." instead of "The API didn't answer while checking the file…". This covers a request in flight when the connection drops and a check the Source select starts while offline. An import adds "; a retry never imports the same file twice.". The cause is read when the request fails, as `actionFailure` does, so the line still names the connection after you reconnect.
2. **imp-157.** Offline, Retry on a stale line or a panel error is locked like Refresh. It stays focusable (`aria-disabled`), it's dimmed with tokens, and its TapTooltip gives "You're offline. Reconnect to use this.". A press shows the reason, sends nothing and leaves focus on Retry. On reconnect TanStack's background refetch runs as before.

## What changed

- `import-panel.tsx`: both mutations get `onError`, which records `!onlineManager.isOnline()` at failure time. Offline, the error line and its alert use `CHECK_OFFLINE` / `IMPORT_OFFLINE`. The alert drops "Select Retry to try again." because the offline copy already says Retry. A Problem answer (a 422 or 503 with an Error ID) and every online failure read as before (`import-announce.spec.ts` still checks the online transport copy).
- `retry.ts` `useRetry`: it reads `useOnline()`. A press while offline returns at once: no `scope.press` and no refetch, so imp-135's scope never follows it. `online` is returned to the two atoms. `useRetryScope` is unchanged: a press made online is still followed through a drop, as DEC-217 (a) says.
- `atoms.tsx` `PanelError` and `StaleLine`: Retry sits in `TapTooltip` with `OFFLINE_HINT` while offline, and gets `aria-disabled` plus the token dimming every locked control uses (DEC-185). The secondary Retry dims its text. The primary Retry takes the secondary tokens, like Import N rows. TapTooltip is inert without a hint, so the button stays the same element and keeps focus when the connection drops or returns (DEC-206 e). The run drawer's errors use the same atoms, so they get the same lock.
- `e2e/data-health/fixtures.ts`: imp-134's offline network helper moved here as `offlineNetwork`, and `offline.spec.ts` imports it. It's now shared by three specs.

### Why a lock and not an inline message (DEC-220)

The brief allowed either. The lock is DEC-206's pattern for every offline control ("Mutations disabled with tooltips" in UI States), and it matches Refresh, which sits above these lines and is already locked. It keeps imp-135 intact without special cases. An offline press never starts a refetch, so no scope follows it, nothing is announced (DEC-217's alert stays for pressed failures only) and focus never moves. An inline message beside an enabled Retry would add a second kind of announcement and a Retry that looks available under a banner saying refresh is off.

## Leftovers (proposed backlog rows, not changed here)

1. **P3, Claude, `atoms.tsx` `TapTooltip`:** a press on a locked control whose reason is already open (Enter after keyboard focus, or a click after the 400 ms hover) hides the reason, because a press toggles it. This affects Refresh, the switches, Run now, Choose CSV… and now Retry, and it predates this task (imp-073). A press on a locked control should open or keep its reason, never close it.
2. **P4, Claude, `retry.ts`:** a keyboard user resting on a locked Retry when the reconnect refetch restores the panel loses focus to `<body>`. An unpressed refetch moves no focus (DEC-217 d). The scope could give the heading the lost focus when its focused Retry leaves on reconnect.
3. **P4, Claude, `atoms.tsx` `TapTooltip`:** at 375 the reason above a focused Retry covers the error's Error ID line while it's open (`panel-375-*`, `stale-375-*`). TapTooltip has no `side` option to put it below.
