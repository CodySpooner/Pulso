## Cause

`imports/csv.py::parse_csv` drops a field from the row dict in two cases: its column is absent, or its cell is blank. The CJ `Row` model then filled those fields with `moq=1` and `warehouse_country=None`. The writer assigned both to the existing `SupplierOffer` without checking them. So the second import in the lead probe turned `(5, US)` into `(1, None)`.

## Fix (`packages/sources/src/pulso_sources/cj/csv.py`, DEC-186)

- `Row.moq` is now `PositiveInt | None = None`, so the writer no longer supplies a default of its own.
- **MOQ:** the offer is updated only when a row in the product states one. DEC-074 already rejects a product whose rows state two different MOQs.
- **Warehouse:** only stated countries count. One country sets it, several set it to unknown (as before), and none keeps the stored value.
- **Blank cells mean the same as an absent column.** Both are "no evidence", so the stored value is kept and a CSV can't clear it. Telling blank from absent would mean changing the shared parser and every caller, so I didn't.
- **New offer:** with no MOQ evidence, the existing `supplier_offers.moq` server default of 1 applies (the column is `NOT NULL`, and this task allows no schema change). Its warehouse stays unknown. The limitation is that a stored 1 can't tell a stated MOQ from a missing one (see the follow-up below).
- **Behaviour change for explicit values:** a product with one country-bearing row and one blank row now stores that country. It used to clear the country. Distinct stated countries still clear it, and the existing fixture (CN, US, CN) still asserts `None`.
- **Unchanged:** the `captured_at >= last_seen_at` guard, variant prices through `CSV_WRITER` (change-only), freight rows (whose per-row `origin_country` may still be null), the points guards and caps, the shared parser, DEC-074, the other templates, and Shopify imports.
