# imp-527 + imp-585: New rule with a product picker, and the builder's 422s in words

Claude · branch `CodySpooner/imp-527-rule-product-picker` · DEC-367 (proposed, imp-527) · Phase 4 WF-4 polish · web only: no migration, no API change, no new dependency, no flag.

## What changed

- **New rule on the Rules tab** (`/alerts?view=rules`), beside the evaluation line, with `N` as its key (`aria-keyshortcuts="N"`, title "New rule · N"). N works from anywhere on the tab except a field, a dialog or a menu. Nothing else on /alerts uses N. It presses the button, so focus always comes back to New rule.
- **The builder opens on a product or watchlist step** when it has neither a product nor a rule. The step is a cmdk combobox ("Product or watchlist") over `GET /v1/search`, through `useSearch`, the palette's own query moved into `palette-search.ts` with no change in behaviour: 150 ms debounce, 2-character floor, 100-character cap, kept results, one retry on a 5xx, and one shared cache. Only its products show. The workspace's watchlists sit below them, matched by name.
  - **Picking a product** shows the Product Page's sentence exactly ("When any supplier changes price by 5 %") with focus on Watch.
  - **Picking a watchlist** skips the product. Watch offers only the watchlists and the verb select only the score verbs (DEC-353), starting at velocity. A blank name becomes "Pet: velocity +50%".
  - **Change** (top right) goes back to the search, focused.
  - **States:** under 2 characters (a hint), searching, stale (the last products under the input's spinner, `aria-busy`), no products match (also when only stores or suppliers match), too long, nothing collected yet (with Open Data Health), and search unavailable (with Retry search). A polite live region gives the count ("3 products for “glow”") or the state.
  - The list has a fixed height from 640 px up, so the centred dialog doesn't move while typing. On a phone the full-height sheet gives it the rest of the screen.
- **imp-585, 422s in words.** `fieldErrors` uses one table, field → range: "Enter a % above 0, up to 1,000.", "Enter 0 to 1,000,000 units.", "Saturation runs from 0 to 100.", "Choose above or below." and "Give the rule a name, up to 120 characters." It applies to Pydantic's range, type, missing, literal and length errors, matched by their `type` (`greater_than*`, `less_than*`, `float_*`, `finite_number`, `missing`, `literal_error`, `string_too_*`). Any other message keeps the API's text, under its field (an unknown param, a NUL in a name) or under the form.
- **Empty Rules tab:** the copy now says "Choose New rule, then a product or a watchlist…". The Discover link is gone, and the state has no second button with the same name.

## Clicks (the main flow)

| Flow | Clicks | Keyboard |
|---|---|---|
| A product rule from the Rules tab, default verb (supplier price ±5%) | **3**: New rule, the product, Create rule (plus a few letters typed) | N, letters, Enter (picks the highlighted product), Tab, Tab, Enter |
| Same, another verb | 4 (the verb select) | as above, plus the verb's first letter on Event |
| A watchlist rule (velocity +50%) | **3**: New rule, the watchlist, Create rule | N, Enter (with no query the first watchlist is highlighted), Tab, Tab, Enter |
| From the Product Page (unchanged) | 2: Create alert, Create rule | |

Every one of these goes keyboard-only with a visible focus ring. The e2e checks `:focus-visible` on Watch, and that focus is back on New rule after save and after Escape.
