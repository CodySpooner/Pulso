## Coverage (on origin/main `26335b6`, after p2-16 and p2-15 merged)

`COVERED = ("/v1/products", "/v1/search", "/v1/profit", "/v1/categories")`. Every 2xx response under these prefixes is walked, so a new endpoint under them is covered as soon as it exists. The test names the 12 operations it covers, and fails if a prefix stops reaching one of them:

| Operation | Path |
|---|---|
| `list_products` | `GET /v1/products` |
| `get_product` | `GET /v1/products/{product_id}` |
| `get_product_overview` | `GET /v1/products/{product_id}/overview` |
| `get_product_sellers` | `GET /v1/products/{product_id}/sellers` |
| `get_product_series` | `GET /v1/products/{product_id}/series` |
| `list_product_notes` / `create_product_note` | `GET` / `POST /v1/products/{product_id}/notes` |
| `list_product_tags` / `put_product_tags` | `GET` / `PUT /v1/products/{product_id}/tags` |
| `search` | `GET /v1/search` (p2-16) |
| `calc_profit` | `POST /v1/profit/calc` |
| `list_categories` | `GET /v1/categories` |

**Not covered**, because they return no product data: `/v1/me`, `/v1/settings` (workspace inputs; p2-15's new fields don't change that), `/v1/admin/*` (Data Health's run and source records), `/healthz` and `/readyz`.

**Exemptions** (`EXEMPT`, each with its reason in the test). Only row identifiers qualify. The test fails on an exemption the check no longer flags.

| Field | Reason |
|---|---|
| `CategoryOption.id` | a taxonomy id (Google's), not a measurement |
| `StoreHit.id` | the `stores` row the palette opens, not a measurement |
| `SupplierHit.id` | the `suppliers` row the palette opens, not a measurement |

**What the wider check flagged, and the fix.** Only `POST /v1/profit/calc` was flagged. `ProfitCalc` had 14 numbers (lines, rates and the echoed ids) and provenance only per input in `sources`. It gains a required `as_of: AwareDatetime | null`, set to the oldest `captured_at` among `sources`. That is DEC-239's "oldest family feeding it". It is null when only settings and owner estimates feed the result, since those have no capture. Nothing is made up; no line, source or `InputSource` shape changes. After the rebase, p2-16's `StoreHit.id` and `SupplierHit.id` were the only new findings, and they're exempt as ids.

## Acceptance

- **The contract test names its operations and passes:** see the table above. `test_every_number_in_a_product_resource_carries_as_of` passes on `26335b6` + this branch.
- **Removing `as_of` from any covered resource fails it:** the mutation test finds 11 carriers (`Sourced`, `Velocity`, `SupplierCost`, `ProfitCalc`, `InputSource`, `SellerRow`, `Spread`, `SpreadPoint`, `Counts`, `SeriesDay`, `Point`). It removes `as_of` from each one in a deep copy of the spec, and asserts that the check reports a new finding every time.
- **RED before the fix:** before `ProfitCalc.as_of`, the contract test failed on the 14 `ProfitCalc` fields, and the mutation test failed because `ProfitCalc` was not a carrier.
- **Value checks** (Postgres): the FX test's result has `as_of` = 10-23 23:30Z, the snapshots' capture, not the FX rate stored 10-24. Once a 10-19 rate (stored 10-20) bridges the freight, it moves to 10-20 00:00Z. A quantity-2 call with no supplier, fed only by settings, has `as_of` null.
