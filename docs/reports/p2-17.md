Precedence for a product: the first listing whose source category resolves (a `manual` or `ai` mapping row first, then the rules), refined by the first title that matches.

## Choices made under the non-stop rule (all in DEC-253)

- **Paths, not ids, in the rules file**, so a reviewer can read it. TOML because `tomllib` is stdlib (YAML would be a new dependency).
- **Rule categories are re-derived each run:** a product whose `category_source` is `rule` and no longer matches goes back to NULL / NULL. `manual` and `ai` products are never selected, and the UPDATE's WHERE checks again, in case an owner edits mid-run.
- **`category_source` is just `rule`** for both the source-category and title families. The schema's values are `rule · ai · manual`, and `category_mappings.mapping_source` has a CHECK on those values.
- **Normalised mapping keys:** `category_mappings.source_category` stores the casefolded, spacing-collapsed value with `›` read as ` > `, so "Home" and "home" share one row.
- **Tags are not a rule family.** Store tags are mostly merchandising noise. Add them if the collector-host coverage shows a gap.
- **No Celery task.** It was optional in the brief; the one-shot command covers M-6.
- **Merged products** are skipped; reads follow `merged_into_id`.

## Findings

1. **CJ listings carry no category today.** `pulso_sources.cj.parse()` returns id, title, prices and listed count only. The listV2 fixture has no category field, and `Listing.product_type` stays NULL for CJ. The panel's `categoryId` lives only in the raw payload's request params. So the `[sources.cj]` rules (keyed by the seed panel names) have nothing to match until the CJ adapter stores the panel's category name, and CJ products rely on the title fallback until then. Changing the CJ adapter was outside this task's ownership: see the backlog row.
2. **The fixture coverage figure is weak evidence.** All 251 Shopify fixture products are "Fixture product N" with product type "Home", and CJ's are "Fixture pet brush" and "Fixture bowl". The 99.6 % mostly shows that "Home" maps. Measure the real figure with the first `map` on the collector host (the lead step below prints `categorised` / `uncategorised`).
3. **Licence.** Neither the taxonomy file nor its Merchant Center help page states a licence or reuse terms, only Google's generic Terms of Service. Vendoring was authorised in the task brief; it is recorded in DATA_SOURCES and DEC-253, and flagged below for the owner.
4. **Settings need S3 keys for any CLI.** `python -m pulso_core.taxonomy` builds its session from `get_settings()`, which requires `S3_ACCESS_KEY_ID` and `S3_SECRET_ACCESS_KEY` even though the taxonomy never touches S3. The scratch run passed dummy values inline (not written to any `.env`). The collector host has real ones. This is pre-existing behaviour, shared by `alembic` and the S3 helper.
