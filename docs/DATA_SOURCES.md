## Rules (summary of SPEC §4.2 plus agreed additions)

1. Prefer official APIs. Honest User-Agent naming Pulso with a contact URL. Respect robots.txt and rate limits.
2. No CAPTCHA solving, no scraping behind logins, no anti-bot evasion, no rotating/residential proxies, no forged request signatures.
3. Blocked = auto-disable + Data Health alert. Default block rule: 5 consecutive 429/430/403 responses, or a source-specific fatal code (listed per source). Never retry from a different IP.
4. Every source has a manual CSV import (a collector run with `trigger=csv`, parsed by the adapter's `parse_csv()`).
5. Sources whose terms forbid storage are live lookup only (Redis, 24 h TTL), never written to `raw_payloads`, snapshots or features. Today: AliExpress.
6. No vendor-scraped data (Apify, Bright Data, ScrapeCreators, etc.) without an explicit owner decision in `docs/DECISIONS.md`. Default until Phase 1 exit: official sources + CSV.
7. Never use the Shopify Storefront API or Global Catalog to collect or cache data; never probe `/cart*`.
8. Store no personal data we don't need (no reviewer names; advertisers as page/business identifiers only). Secrets only in `.env`; request params in `raw_payloads` are stored with secrets stripped.

## Listing images (`listing_images`)

- **What:** each current listing's main image (lowest `images.position`, newest row on a tie), fetched once into the object store and hashed (64-bit DCT pHash) for product matching (SPEC §4.4, M-2 part a, DEC-240). Embeddings are M-2 part b.
- **Hosts expected:** the Shopify stores' image CDN (catalog `images[].src`, normally `cdn.shopify.com`) and CJ's product image CDN (host to confirm from stored CJ rows; CJ images may sit on a third-party CDN). **Robots and terms: to verify before enabling** (P2-04 sent no request to any host). Only exact `https` hosts on port 443 listed in `IMAGE_HOSTS` are fetched; the default is empty, so enabling the source alone fetches nothing. Entries must be bare lowercase DNS names (no scheme, port, userinfo, path or IP literal), or settings fail at start-up. A URL with userinfo or a backslash in its host part counts as unlisted. A day whose due images are all unlisted reads `partial` with `NoListedHost` (DEC-242). List a host here with its checked robots.txt and terms before adding it.
- **Access:** `GET https://<host>/robots.txt` once per host per run, then the image URL. Honest User-Agent `PulsoBot/0.1 (+PULSO_BOT_CONTACT)`, no cookies, no redirects followed, no proxy. A robots.txt that isn't 2xx fails closed for that host for the run; `Disallow` fails the image (`RobotsDisallowed`); `Crawl-delay` and `Request-rate` can only slow the host: the spacing is the largest finite `Crawl-delay` anywhere in the file (fractions included) or the `Request-rate`, and `Request-rate: 0/n` refuses the host for the run (`RobotsZeroRate`). A host whose next allowed request falls past the run's budget sits the run out with no penalty, and the other hosts carry on (DEC-242).
- **Limits:** at most `IMAGE_REQUESTS_PER_MINUTE` per host (default 30, capped at 30), spaced evenly; daily at 06:00 UTC on the `collect` queue, after the day's Shopify and CJ runs; at most 30 × 45 = 1,350 images per host per run (the generic 45-minute budget). Framework rules apply: `Retry-After`, 5xx retries with backoff, and 5 consecutive 429/430/403 responses disable the source with one Data Health event. A robots.txt answer that isn't a block leaves that count as it was, so image blocks reach it while robots.txt still answers 200 (DEC-242). A block stops the run at once.
- **Validation (before anything is stored):** `Content-Type` image/jpeg, png, webp or gif; at most 5 MiB (the read stops one byte past it); at most 40 megapixels from the header before decoding; Pillow limited to those four formats; a full clean decode. A rejection fails that image with `ImageContentType`, `ImageTooLarge` or `ImageUndecodable` and a log line; nothing is written.
- **Stored:** the image bytes once, as the run's raw capture (`raw/listing_images/<UTC date>/<sha256>.bin.gz`, gzip with the original bytes' sha256); `images.storage_key` is that key and `images.phash` the signed hash. Robots bodies are captured like every adapter's. **Retention:** follows raw payload retention (none is enforced yet). A future retention job must clear `storage_key` and `phash` with the object or exempt image captures.
- **Re-runs:** an image with a `storage_key` is never fetched again. A failed image waits 20 h, doubling to at most 30 days, counted from its own run evidence; an image the run never reached (deferred, robots unavailable) is retried next run without penalty.
- **CSV fallback:** none of its own: image URLs arrive with the listing sources and their CSV imports. An unfetched image has no pHash, and matching treats it as a missing input (weight 0, DEC-040).
- **Risk:** CDN terms unchecked; a 403 for a single missing object counts toward the source-wide block rule. **Cost:** free. **Status:** planned: built and registered disabled (`sources.id` 6); enabling needs an owner decision (DEC-073 does not cover it). **Phase:** 2.

- **Signal / metric:** the official general (MFN) duty rate for each HS-6 candidate in `docs/HS6_SEED_CATEGORIES.md`, shown as a *suggestion* on the Profit tab's duty line, never auto-applied. Metric: seed categories with an official general-rate suggestion; baseline 0 of 10.
- **Verified:** the [data.gov listing for the 2026 HTS](https://catalog.data.gov/dataset/harmonized-tariff-schedule-of-the-united-states-2025) has publisher USITC Office of Tariff Affairs and Trade Agreements and a public-domain licence. It offers CSV, XLSX and JSON for the Basic Edition and Revisions 1–21 (for example `https://www.usitc.gov/sites/default/files/tata/hts/hts_2026_revision_21_json.json`), and was last checked 2026-10-09. The [2022 listing](https://catalog.data.gov/dataset/harmonized-tariff-schedule-of-the-united-states-2022) also names an "HTS REST API … in JSON format".
- **Unknown:**
  - The REST API's endpoints, limits and terms: usitc.gov returned 403 to every automated fetch on 2026-10-23.
  - How Chapter 99 additional duties (China-origin and others) appear in the export.
  - The HS-6 → HTS-8/10 choice for 7 low-confidence mappings.
- **CSV fallback (primary at first):** the owner downloads the revision's JSON or CSV in a browser and imports it. Any automated fetch needs its own DEC after a by-hand docs check. The general rate is never the whole duty; the owner confirms the total.

#### openFDA device recalls (`openfda_device_recalls`)
- **Signal / metric:** FDA device recalls and enforcement reports → possible-recall flags for device-like products in the Beauty Tools and Fitness seed categories, beside CPSC. Metric: share of tracked products in those categories checked against FDA device recalls; baseline 0%.
- **Verified:** the [device endpoints](https://open.fda.gov/apis/device/) include `device/recall` ("Recalls") and `device/enforcement` ("Recall enforcement reports"). [Authentication](https://open.fda.gov/apis/authentication/): without a key, 240 requests/min and 1,000/day per IP; with a free key ("free of charge"), 240/min and 120,000/day per key.
- **Unknown:** terms of service text (not opened); how many dropship gadgets are FDA devices at all.
- **CSV fallback:** an owner-supplied recall CSV.

#### Merchant API price competitiveness (part of `merchant_bestsellers`)
- **Signal / metric:** Google's `benchmark_price` beside the owner's own price for products in the owner's Merchant Center. Metric: pushed products with a benchmark price; baseline 0.
- **Verified:** the [market guide](https://developers.google.com/merchant/api/guides/reports/understand-the-market) shows `price_competitiveness_product_view` (id, title, brand, price, report country, `benchmark_price`) covering "the same products that you sell". It has the same eligibility wording and the same Merchant Center terms as Best Sellers.
- **Unknown:** coverage for products without GTINs (likely low).

#### Owner's own accounts (personal use, DEC-136)
These read only the owner's own data. They are listed here because each still adds a source, scope or secret that needs a DEC.
- **ShopifyQL `sessions` (`shopify_own_analytics`):**
  - **What it gives:** sessions, cart-addition sessions and conversion rate by `landing_page_path` (per product page) for the owner's stores, for the Testing Board. Sources: [sessions schema](https://shopify.dev/docs/api/shopifyql/latest/schemas/sessions_and_behavior/sessions) and [shopifyqlQuery](https://shopify.dev/docs/apps/build/shopifyql/graphql-admin-api).
  - **Requirements:** API 2025-10 or later, the `read_reports` scope and Level 2 protected customer data. [Protected customer data](https://shopify.dev/docs/apps/launch/protected-customer-data): custom apps "Always available"; admin-created custom apps "Varies by plan".
  - **Risk:** Shopify API License §2.3.24 (see `shopify_stores`) applies before any model training on this data.
- **Meta Marketing API Insights (`meta_ads_insights`):**
  - **What it gives:** daily spend and results for the owner's own ad account, replacing manual or CSV ad spend.
  - **Access:** [authorization](https://developers.facebook.com/docs/marketing-api/get-started/authorization) says that for an app managing only the developer's own ad account, "standard access to the `ads_read` and `ads_management` permissions are sufficient".
  - **Unknown:** the same page calls the default Limited tier "For development only. Not for production apps running for live advertisers" and "Heavily rate-limited per ad account". Which tier a one-owner app needs is unverified.
